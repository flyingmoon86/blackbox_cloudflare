# 完整备份与隔离恢复

备份保存 D1 的完整 SQL、R2 对象与元数据、数据库记录摘要、文件引用清单和 SHA256 校验。保留旧快照，不把线上删除同步为本地删除。默认目录 `migration-work/archive-backups/` 已被 Git 忽略，包含账号与资料数据，不提交仓库。另复制一份完整备份目录到独立磁盘或受控备份位置；仅在同一磁盘留副本不能防磁盘损坏。

## 创建与校验

```powershell
npm run archive:backup
npm run archive:verify -- --snapshot "D:\备份\snapshots\实际快照目录"
```

第一条默认使用当前仓库 `wrangler.jsonc` 的正式 D1、R2 配置，通过 Wrangler 导出 D1，通过 Cloudflare REST API 只读列举并下载 R2。它不部署 Worker、不修改生产数据。可用 `--directory "D:\备份"` 指定备份根目录。需要能导出 D1、读取 R2 对象的现有 Wrangler 登录或 `CLOUDFLARE_API_TOKEN`，不打印凭据值。

文件按内容哈希保存在 `objects/`；下一次快照只下载变化的对象，同时重新校验复用文件。每个 `snapshots/<时间>/` 保存数据库 SQL 与清单。**复制快照时必须一起复制备份根目录的 objects，不要只复制 snapshots。**

只有数据库外键/完整性、文件引用、下载长度/内容及前后 R2 清单校验通过，才创建 `complete.json`。中断、认证失败、缺文件或校验失败的目录只有不完整状态，不能作为恢复来源。工具会拒绝缺游标的截断清单。

D1 与 R2 没有跨服务原子快照。备份期间应暂停人工资料修改与上传；前后文件清单不同会让备份失败，需要重试。工具不自动停站。备份不包含尚未合并的分片内容，恢复后的未完成上传应重传。旧命令 `db:production:backup` 仍只是 D1 导出，不视为完整网站备份。

## 隔离恢复

```powershell
npm run archive:restore -- --snapshot "D:\备份\snapshots\实际快照目录" --target "D:\演练\全新的恢复目录"
```

恢复先完整校验快照，再导入本地 D1 与本地 R2，逐表核对记录数及内容摘要、检查外键，逐文件核对 SHA256 和数据库引用。成功后写入目标目录的 `restore-report.json`。目标必须是不存在的新目录，不能覆盖源码或备份。配置中的数据库和桶为专用本地演练名称，恢复命令没有远程恢复选项。

此演练验证数据和文件恢复，不自动部署网站，也不表示生产域名、密钥或线上登录已验证。需要回到生产时，先以恢复副本评估线上新增数据，再制定单独发布步骤，不把演练数据库整库覆盖生产。

