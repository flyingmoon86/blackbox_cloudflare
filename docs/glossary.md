# 术语表

> 项目里出现的名词解释。按主题分组，不熟哪个查哪个。

## Cloudflare 组件

| 术语 | 含义 |
| --- | --- |
| **Worker** | Cloudflare 上的服务器程序。本站全部动态请求（页面生成、上传、审核）都由一个 Worker 处理。主站和后台共用同一个。 |
| **D1** | Cloudflare 的 SQL 数据库。本站用它保存结构化资料：账号、作品、成员、文件说明、审核状态。所有「能不能看」的判断都在 D1。 |
| **R2** | Cloudflare 的对象存储（类似网盘）。只保存文件内容（照片、剧本、音频），不做权限判断。 |
| **Static Assets** | 静态文件直出服务。`public/` 里的脚本、样式、图片直接返回，不走业务逻辑。 |
| **Hono** | 本站使用的 Web 路由框架（一个 TypeScript 库）。负责把不同网址交给对应的处理函数。 |
| **Wrangler** | Cloudflare 的命令行工具。本地开发、数据库迁移、部署都通过它。仓库里由 `scripts/wrangler.mjs` 封装调用。 |
| **Miniflare** | 本地模拟 Cloudflare 环境的工具（跑测试用）。 |
| **Cron / 定时触发器** | 按时间表自动运行的任务。本站每小时第 17 分钟执行清理维护。 |
| **Smart Placement** | Cloudflare 的智能部署位置功能。生产配置已开启，但收益未测量验证。 |

## 站点业务

| 术语 | 含义 |
| --- | --- |
| **作品（work）** | 一部剧。网站资料的顶层单位。 |
| **演出版本（edition）** | 作品的一次演出（通常按年份）。一部作品可以有多个版本，每个版本有独立的演职和资料。 |
| **演职记录** | 某成员在某版本中担任的角色或职务。支持 AB 角（同角色多人）、一人多角。 |
| **资源（resource）** | 一份资料：照片、剧本、音频等。新上传须选择作品和版本；历史资料可能没有关联。作品和版本均为空才归入“未关联作品”，关联失效另列为异常。 |
| **审核** | 资源公开前的把关。管理员投稿或符合低风险规则自动批准，其余等人工审核。文件进入 R2 不等于公开。 |
| **可见性** | 作品是否对访客公开。隐藏作品只有管理员能看，其下资源也不会因文件地址泄露。 |
| **容量台账 / 预算** | 网站自己记的文件空间账（约 9 GB 上限），用已存文件 + 预留空间计算。不是 R2 桶的实际容量。 |
| **上传任务** | 一次上传的生命周期记录，最长保留 24 小时。超时进清理队列。 |
| **清理队列（file_cleanup_task）** | 待删除文件的重试清单。上传失败或删除失败的对象登记在此，由定时任务重试。 |
| **批量导入演职记录** | 管理员上传表格一次性录入多人演职。整批成功或整批回滚。 |

## 安全与身份

| 术语 | 含义 |
| --- | --- |
| **会话（Session）** | 登录后的凭据状态。浏览器保存一个**签名 Cookie**，有效期 14 天。 |
| **签名 Cookie** | Cookie 内容带 HMAC 签名。网站用它检查凭据有没有被改动，再查 D1 确认账号仍有效。 |
| **CSRF 令牌** | 防跨站请求伪造。写入操作要求请求来自本站且携带令牌，防止别的网站借用已登录浏览器发起修改。 |
| **scrypt** | 密码哈希算法。密码以 scrypt 形式保存；网站保留对历史密码格式的验证能力。 |
| **Turnstile** | Cloudflare 的人机验证（点选挑战）。生产只用于注册、匿名反馈等指定流程。 |
| **同源检查** | 验证请求的 Origin 头是否来自本站域名，是写入操作的第一道防线。 |
| **限流** | 对频繁请求的速率限制，防止刷接口。 |
| **admin 门禁** | 后台域名 `admin.npublackbox.online` 的入口拦截。第一层防护；真正的权限在每个操作的服务端逻辑里。 |

## 发布与运维

| 术语 | 含义 |
| --- | --- |
| **迁移（migration）** | 数据库结构变更脚本。`migrations/` 里的编号 SQL 文件，按顺序执行。新增结构用新编号文件，不改旧文件。 |
| **D1 导出 / 备份** | 把生产数据库导出为 SQL 文件。**不含 R2 文件**，单独恢复不了完整网站。 |
| **冒烟检查（smoke test）** | 发布后请求 9 个公开地址验证基本响应。只发现明显故障，不代替人工验收。 |
| **部署干跑（dry-run）** | 只构建不发布，用于部署前检查。 |
| **Server-Timing** | 响应头里的总处理耗时。不是 CPU 时间，也不是纯数据库耗时。 |
| **边缘缓存** | CDN 层的短期缓存。图片可能被缓存以减少重复读取，但每次访问仍先经过权限检查。 |
| **R2 直传（presigned upload）** | 浏览器直接向 R2 上传文件的模式（不经过 Worker 分片）。代码已支持，线上是否启用未验证。 |
| **R2 CORS** | R2 的跨域访问规则配置，直传模式需要。`npm run r2:production:cors` 可设置。 |

## 开发工具

| 术语 | 含义 |
| --- | --- |
| **`npm run dev`** | 启动本地开发服务器（本地独立 D1/R2，与线上互不影响）。 |
| **`npm run db:init`** | 建立本地数据库并应用全部迁移。 |
| **`npm run deploy:check`** | 发布前全套检查：格式、类型、测试、构建干跑。**不发布。** |
| **`npm run test:backend`** | 运行 `scripts/backend/` 下的后端测试。 |
| **`assets:build`** | 构建静态资源产物（生成 `src/generated/`）。多个 npm 命令会自动先执行。 |
