# 开发维护

## 系统与修改入口

主站和独立后台共用一个 Cloudflare Worker（Hono）、D1 数据库及 R2 文件存储。静态文件由 Static Assets 返回。路由验证请求和权限，服务层处理业务，视图输出 HTML；用户文本输出前转义。后台入口门禁不能替代操作本身的鉴权。

- 请求装配：`src/index.ts`、`src/middleware/`；登录和会话：`src/routes/auth.ts`、`src/auth/`。
- 页面：`src/views/`；统一导航和资源装配：`layout.ts`；共享 HTML 与小组件直接从基础模块引入，避免经兼容 `src/views.ts` 反向循环依赖。
- 作品/演出版本：`src/routes/productions.ts`、`src/views/productions.ts`；公开/隐藏规则：`src/services/production-visibility.ts`。
- 资料/上传/审核：`src/routes/resources.ts`、`uploads.ts`；文件读取、容量、清理和审核在 `src/services/`、`src/storage/`。
- 队员：`src/routes/members.ts`；精选照片：`member-photos.ts` 路由与视图、`member-photo-storage.ts` 服务；去向：`member-records.ts` 路由/服务/视图。
- 公告：`src/routes/content.ts`、`src/shared/announcement-markdown.ts`；保留转义、链接协议白名单和正文长度边界。
- 演职导入：`src/routes/credit-import.ts`、`src/services/credit-import/`、`templates/`；保留 v2 模板及 v1 兼容读取、人工匹配与回滚。
- 增量结构：`migrations/`；测试/工具：`scripts/`；本地运行状态：`.wrangler/`。已执行迁移不能改写，不能把运行状态或真实备份当作缓存清空。

Worker 是服务器程序，D1 保存记录和权限，R2 保存文件，Static Assets 保存公开脚本/样式。D1 与 R2 没有跨服务原子事务，文件删除通过持久清理任务恢复重试。

## 当前业务规则

作品可有多个演出版本，演员、分工和资料要归属正确版本；一个作品保留一张卡片。AB 角与一人多分工允许，只有作品、版本、队员、类别、角色完全相同才重复。非作品资料可存在，新剧照必须归属作品与版本；剧照在作品中查，资料库列其他文件。

游客浏览公开档案、批准资料的低清图/封面，可限频献花及匿名提建议。普通账号可下载可访问资料、上传、申请作品与队员认证；认证通过后才可改本人档案和申请演职分工。认证优先绑定已有档案，再申请新建；贡献者不自动取得队员身份。

管理员上传直接入库，普通账号与认证队员上传一律人工审核；不存在低风险自动入库。新视频上传关闭，保留历史视频读取。文件内容检查不等于恶意内容识别。上传保留分片幂等、租约、容量预留、完成重试与可恢复清理。`UPLOAD_MODE=proxy` 明确走 Worker，`direct` 要求完整签名直传配置，不能缺配置就自动切换；旧任务沿原模式继续。

私有文件逐请求鉴权，先于 HEAD、Range、304 和文件读取；禁止仅靠前端隐藏入口。隐藏作品不能泄漏到资源下载/预览。待审资料仅提交人和管理员可见，原件及完整剧本/媒体需登录。

个人精选照片须审核通过且同意队内展示，仅认证队员和管理员可见；撤回、归档及认证撤销应立即生效，恢复归档不自动恢复同意。毕业去向独立维护，仅本人和管理员可见，保存直接生效，不要求核实，不允许共享摘要。保研率分母为已填写且已确定去向的人数；“还没定”、未填、未知及拒绝提供排除，分母为零不显示虚假比例。旧内部照片和历史记录不自动转换成新精选照片。

建议正文、邮箱不公开；署名遵循同意，提交建议不会自动加入鸣谢。删除/解绑账号保留适用的档案和已审资料，不删除当前或最后一位管理员；会话权限每次检查。临时管理员首次登录强制改密，后台与主站 Cookie 各自独立。

## 页面与构建

维持 Hono 服务端 HTML、原生 JS/CSS，围绕真实剧照、克制大字、细线和留白维护，不引入前端框架。主站桌面首页分场景；手机自然浏览。作品、资料、指南和长表单允许滚动，不套用旧“全站禁止滚动”。颜色遵循严格 HEX 主题，保留危险/成功语义。键盘、触屏与减少动画下功能可用；视觉变更实际检查桌面和手机，不能用源码推断代替渲染。

浏览器模块在 `src/client/`，入口名单在 `scripts/client-entries.mjs`；改源码后运行 `npm run assets:build`。生成的 `public/*.js`、`public/assets/` 和 `src/generated/` 不手改。`public/system-scene.entry.js` 同样经构建输出。其他未迁入模块的 CSS/JS 仍在 `public/` 维护。新增静态资源按需加入 `scripts/build-assets.mjs`，通过 `assetUrl()` 读取哈希路径；保留旧哈希文件供已打开页面使用。

修改后先跑相关测试、类型、格式；提交前的完整检查见 [发布与恢复](发布与恢复.md)。涉及权限时按游客、普通账号、本人、其他队员、管理员检查，使用合成数据。HTML、直链、导出及条件请求均需覆盖。

## 图文手册更新

正文只改 `src/content/member-handbook.ts`；网页为 `src/views/help.ts` 与 `public/handbook.css`。保留短步骤和截图，PDF 带封面、可点击目录及管理员附录；网页按当前管理员身份输出附录，PDF 附录本身无账号访问控制。

执行 `node scripts/export-handbook.mjs` 后，用安装 ReportLab、Pillow、pypdf 的 Python 运行 `scripts/build-handbook-pdf.py`。字体取 Windows 微软雅黑与宋体，其他机器需调整字体路径。成品写入 `docs/handbooks/`；中间 JSON、预览和检查证据写入任务 `artifacts/`。

重新截图：运行 `scripts/handbook-preview.mjs`，环境变量 `HANDBOOK_PREVIEW_PORT=8794`，再运行 `node scripts/capture-handbook.mjs`。截图使用演示身份/合成数据，源图放 `public/images/handbook/` 作为站内资源。运行 `npm run assets:build`，在端口 8795 启动同一预览服务，执行 `node scripts/check-handbook.mjs`。该服务仅监听回环地址并拒绝写请求，关闭后丢弃内存数据。Playwright 依赖默认取本机 bundled runtime；可用 `PLAYWRIGHT_MODULE` 指定模块。PDF 渲染后逐页查看，并核对目录与页脚返回链接。

## 常见排查

- 上传后别人不可见：查审核状态、作品可见性与版本归属。无法预览/下载：先查登录与权限，再查对象是否存在，不放宽鉴权来掩盖故障。
- 页面没更新：检查改的是源码还是生成文件、资源构建是否执行以及引用哈希；不要直接修补构建输出。
- 本地正常、线上未生效：本地迁移不作用于生产，Git 推送也不是部署。先查发布记录，不自动迁移或覆盖线上数据。
- 写入请求超时或结果不明：先刷新/只读查询核对状态，再决定重试，避免重复提交。
- 登录/后台异常：查主机、账号状态、会话和强制改密要求，不打印 Secret、Cookie 或密码。
- 构建失败：分清依赖、类型、格式、测试和配置错误。缺少浏览器/编译工具只能说明未验证，不能声称功能或视觉通过。
