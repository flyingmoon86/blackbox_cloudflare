# 代码结构与维护

本文件说明网站代码的维护边界。测试结果与验收证据单独记录在[验证记录](验证记录.md)，发布步骤见[本地验收指南](本地验收指南.md)。

## 服务端页面：按功能拆分，依赖保持单向

路由负责请求参数、登录权限和响应；服务负责可复用的查询与业务规则；视图负责生成 HTML。新增功能优先放进对应模块，不把业务查询塞进页面模板。

- `src/views/html.ts`：`escapeHtml`、状态提示等基础 HTML 工具，不依赖具体页面或页面外壳。用户内容进入 HTML 前仍需转义。
- `src/views/layout.ts`：统一页面外壳、导航、脚本与样式装配。具体页面调用 `layout()`。
- `src/views/shared.ts`：分页、年份选择、图标等小型组件；按需引用 `html.ts`。
- `src/views/account.ts`：登录、注册、认证引导和个人中心页面。
- `src/views/members.ts`：队员列表、详情、编辑、建档与申请页面。
- `src/views.ts`：保留旧调用方的兼容导出，不再承载页面实现。

新视图直接从 `./html`、`./layout` 引入基础能力。`layout.ts` 使用的导航、舞台和公共组件也直接依赖基础模块，不能回头从 `../views` 兼容入口导入，避免“入口 → 组件 → 入口”的循环依赖。

`src/shared/navigation.ts` 统一五个公共导航页的名单，供服务端缓存、视图入口和浏览器预取使用；调整导航预加载范围时从这里修改。

## 功能扩展从哪里开始

- **首页和舞台体验**：`src/views/home.ts`、`src/views/stage-art.ts`；舞台素材与配置逻辑在 `src/services/stage-visuals.ts`。页面是否装载某个脚本由 `src/views/layout.ts` 控制。
- **账号与队员档案**：账号路由在 `src/routes/auth.ts`，队员路由在 `src/routes/members.ts`；模板分别在 `account.ts`、`members.ts`。权限与写入校验留在路由和服务层。
- **作品与演出版本**：`src/routes/productions.ts` 配合 `src/views/productions.ts`；作品可见性规则集中在 `src/services/production-visibility.ts`。
- **资料与审核**：`src/routes/resources.ts`、`src/routes/uploads.ts`；可复用的查询、文件读取和审核逻辑在 `src/services/resource-queries.ts`、`resource-files.ts`、`reviews.ts`。
- **管理员档案统计**：`src/routes/admin.ts` 连接 `src/services/archive-statistics.ts` 和 `src/views/archive-statistics.ts`。修改筛选或统计口径时同步核对查询、分页参数和页面回显。
- **批量演职导入**：`src/routes/credit-import.ts`、`src/services/credit-import/` 和 `src/views/credit-import.ts`。解析、校验、暂存、提交已有独立文件，继续按职责扩展。

数据结构变化通过 `migrations/` 增加迁移；改展示通常无需数据库迁移。资源权限判断先于文件读取，不能由浏览器预加载脚本代替。

## 浏览器源码与构建输出

以下三个入口在 `src/client/` 维护，模块拆分只发生在构建时：

- `curtain-boot.js`：首次进入的加载生命周期；`curtain/scene.js` 生成装饰幕布。样式和纹理继续维护在 `public/curtain.css`、`public/images/`。
- `navigation-preload.js`：公开页面的预加载调度；`preload/discovery.js` 发现允许预热的资源，`preload/assets.js` 负责资源请求、去重与取消。
- `work-browse.js`：作品浏览入口；`work/warm-previews.js` 预热封面，`work/detail-cover.js` 渐进显示封面，`work/return-position.js` 恢复返回位置，`work/policy.js` 放共享的网络与 URL 判断。

`npm run assets:build` 运行 `scripts/build-assets.mjs`，顺序为：

1. 将三个入口各自打包为一个普通 IIFE 脚本，写入 `public/curtain-boot.js`、`public/navigation-preload.js`、`public/work-browse.js`。模块拆分不增加浏览器运行时的模块请求；幕布入口保留同步启动和 `document.currentScript` 的使用方式。
2. 对脚本、样式和列入清单的图片生成内容哈希副本，写入 `public/assets/`。
3. 生成 `src/generated/assets.ts` 映射；模板通过 `src/views/assets.ts` 的 `assetUrl()` 获取资源地址。

不要手改上述三个 `public/*.js` 输出、`public/assets/` 或 `src/generated/`。其他未迁入 `src/client/` 的脚本和样式仍以 `public/` 文件为源码；例如 `public/app.js`、`public/work-browse.css`。另一个已有打包入口是 `public/system-scene.entry.js`，其 `public/system-scene.js` 同样由构建生成。

新增独立浏览器入口时，将其加入 `scripts/client-entries.mjs` 的入口清单和构建脚本的哈希资源清单，再由页面模板按需引用。开发监听与构建共用入口清单，生成文件排除在监听外，避免触发重复构建。更新素材需同步资源清单；不要为保持旧 URL 而覆盖旧哈希文件，构建会保留它们供已打开的页面继续使用。

## 开发与验证

`npm run dev` 启动前会构建一次，运行期间由 `scripts/wrangler.mjs` 自动监听 `src/client/`、`src/shared/` 等资源源码并重新构建；完成后刷新本地页面。单独构建使用 `npm run assets:build`。`typecheck`、`test:backend`、`deploy:check` 的 npm 前置脚本也会构建资源。

按改动选择检查：

```bash
npm run assets:build
npm run typecheck
npm run test:backend
npm run deploy:check
```

`deploy:check` 包含格式、类型、测试和生产配置的 dry-run，不会发布网站。直接执行某个测试文件时不会触发 npm 前置构建，先手动运行 `assets:build`，以免测到旧输出。

首次揭幕与内部导航的浏览器检查入口为：

```bash
node scripts/check-work-curtain-browser.mjs
node scripts/check-curtain-visual.mjs
```

这些脚本使用本地临时测试页面，不等于生产验收。页面体验改动仍应检查真实本地页面的桌面、手机、键盘和减少动画模式；档案管理改动应重点复核权限、筛选、独立分页及异常恢复。记录结果时区分源码判断、自动化与人工浏览器观察。
