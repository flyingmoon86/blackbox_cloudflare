# 阶段 0 本地验证记录

日期：2026-09-08

范围：只使用本地 D1 模拟库、固定虚拟密码和测试文字；未连接 Cloudflare 账户、域名、真实数据库、邮件或上传资料。

## 已通过

- Cloudflare Python Worker 能加载 Flask 3.1.3 和 Jinja。
- D1 本地迁移可重复执行；表单写入成功，计数按一次递增。
- Flask 签名 Cookie 和 CSRF 正常：有效令牌写入成功，错误令牌返回 400。
- Flask 能将公开 CSS 转交给 Static Assets，返回 200。
- TypeScript Worker 的 node:crypto 能验证与现有 Werkzeug 相同格式的 scrypt:32768:8:1 测试哈希；本地单次约 54ms。该时间仅是本机结果，不代表云端性能。

## 未通过和已确认限制

- Python Worker 的 hashlib 没有 scrypt，Werkzeug 无法校验现有默认密码哈希。
- Python Worker 的 hashlib 也没有 pbkdf2_hmac；从同步 Flask 路由等待 Web Crypto 会阻塞请求，因此不能采用该临时方案。
- Python Worker 第一次本地加载依赖约 42 秒，热请求恢复正常；这是本地开发冷启动观察值，不能直接推断线上冷启动。

## 已确认路线

- 采用 TypeScript + Hono 的单 Worker 架构。
- 页面、业务路由、认证和静态资源由同一个 Worker 提供。
- D1 保存业务数据，后续由 R2 保存文件；不建立独立 Pages 前端项目。
- 原 Python 网站完整保留，只作功能与迁移结果对照。

## 阶段 1 本地验证（2026-09-08）

- 正式 D1 初始迁移执行成功，共建立 11 张业务表和 1 张大文件上传任务表。
- `npm run typecheck` 通过。
- 匿名首页、静态 CSS 和健康检查均返回 200。
- 错误 CSRF 返回 400，错误密码返回 401 且使用统一错误提示。
- 固定虚拟管理员可用旧站 Werkzeug scrypt 密码登录。
- 用户名登录匹配不区分大小写，与旧数据库常见排序规则保持一致。
- 登录后签名 Cookie 会话可读取，退出后会话清除。
- 数据库中的 `auth_version` 增加后，已有 Cookie 立即失效，可用于改密码、找回密码和管理员强制下线。
- 测试仅使用本地固定虚拟账号，未写入真实账号、邮箱、数据库和文件。

## 阶段 1 结论

账号基础链路可继续扩展；云端验证前仍需替换 Wrangler 配置中的占位数据库 ID，并通过 Secret 保存会话密钥。
