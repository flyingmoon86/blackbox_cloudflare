# 架构与部署

更新日期：2026-09-10。

## 已确认架构

```text
浏览器
  └─ Cloudflare TypeScript Worker（Hono）
       ├─ HTML 页面、路由、认证和权限
       ├─ Static Assets：CSS 与公开图片
       ├─ D1：账号、队员、作品、公告、审核记录和文件索引
       └─ R2：头像、剧照、剧本、音频和视频
```

前端和后端属于同一个 Worker 项目，没有独立 Pages 项目。这样只有一套部署配置、权限逻辑和日志，更适合小团队维护。

## 代码边界

- `src/routes/`：页面和表单入口。
- `src/views/` 与 `src/views.ts`：服务端生成 HTML。
- `src/auth/`：密码哈希与签名会话。
- `src/middleware/`：登录状态和安全响应头。
- `src/http/`：Cookie 与 CSRF。
- `migrations/`：只向前执行的 D1 结构变更。
- `public/`：静态文件。
- `scripts/data/`：旧 MySQL 导出、D1 转换、R2 文件迁移和虚拟验证。
- `migration-work/`：真实迁移中间文件，已被 Git 忽略。
- `legacy-python/`：迁移核对，不部署。

## 大文件方案

1. 登录用户向 Worker 申请上传任务。
2. Worker 检查队员身份、文件类型、大小和作品。
3. 正式环境由 Worker 签发 15 分钟有效的分片 URL，浏览器以 50MB 分片、最多 3 片并发直传 R2。
4. Worker 完成上传并创建 `pending` 资源记录。
5. 管理员审核后资源才进入资料库。
6. 下载时 Worker 校验权限，再提供受控下载地址。

本地没有 R2 API 凭据时，Wrangler 使用 `FILES` 本地 Bucket，分片通过本机 Worker 写入模拟 R2。正式免费环境直接使用 Worker 绑定的 R2 Bucket，浏览器上传仍由 Worker 校验权限并写入 R2，不需要 S3 访问密钥。

正式环境目前只需要一个 Secret：`SESSION_SECRET`。真实值只存 Cloudflare，不写进 Git、文档或聊天。R2 CORS 已配置为仅允许 `https://npublackbox.online` 的 `PUT`，并暴露 `etag`。如果将来改用 S3 直传，再额外创建 `R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`，当前不需要。

## 环境和上线原则

- 本地使用 Wrangler、模拟 D1、模拟 R2 和 `.dev.vars`。
- 测试环境使用独立的 Cloudflare D1/R2，不导入真实敏感数据。
- 正式密钥使用 Cloudflare Secret，不写入 Git 或 `wrangler.jsonc`。
- 全部功能、权限、大文件和数据一致性验收后才绑定域名和切换流量。
- 原 Python 网站和数据备份保留到 Cloudflare 版本稳定运行后。

## 第一次正式部署

以下命令都在 `D:\大三\blackbox_cloudflare` 的 PowerShell 中执行。生产资源已经创建并发布，今后更新按第 6 步开始。

1. 登录 Cloudflare：`npx wrangler login`。
2. 确认 `wrangler.jsonc` 的生产域名、D1 ID 和 R2 桶名分别为 `npublackbox.online`、`77199158-0ae1-48c1-bc0b-afc833b7c0ef` 和 `blackbox-files-production`。
3. 生产 D1 已执行全部迁移；结构变更时运行 `npm run db:production:migrate`。
4. 生产 R2 已创建并配置 CORS。免费方案先把累计对象控制在 10GB 内；本项目视频按 50MB 分片上传。
5. 只在 Cloudflare Worker Secrets 中设置 `SESSION_SECRET`：`npx wrangler secret put SESSION_SECRET --env production`。不要把值写进文件或发到聊天。
6. 修改代码后先运行 `npm run deploy:check`，再运行 `npm run deploy`。
7. 发布后运行 `npm run smoke:production`，并打开首页、登录、作品与资料页面做人工检查。
8. 重大数据库修改前运行 `npm run db:production:backup`。正式上线初期保留原 Python 站和 SQL 备份作回退。

免费方案的边界：Workers Free 每日请求量有上限，单次 Worker 请求体上限为 100MB；本项目单片 50MB，适合内部试运行。R2 免费额度按账户政策控制在 10GB 内，视频总量接近上限时应先清理或升级方案。

相关官方说明：[Workers Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)、[D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/)、[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)、[Workers Secrets](https://developers.cloudflare.com/workers/configuration/secrets/)。

## 费用估算

当前采用免费试运行方案：Workers Free 不产生固定月费，R2 先使用每月 10GB 免费存储额度，D1 使用免费额度。实际请求量、存储量和网络情况仍需在 Cloudflare 控制台观察；超过免费额度后再决定是否升级。

密码找回邮件暂不开放，内部试运行由管理员协助处理密码修改。正式邀请更多队员前，再决定邮件服务商和自助找回流程。

价格会调整，开通前以 [Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)、[R2 定价](https://developers.cloudflare.com/r2/pricing/) 和 [D1 定价](https://developers.cloudflare.com/d1/platform/pricing/) 为准。

## 旧站数据迁移顺序

1. 给旧 MySQL 创建只读账号，运行 `npm run data:export` 生成一致性快照。
2. 运行 `npm run data:transform`，人工查看 `warnings.json`。
3. 在独立测试 D1 执行 `import.sql`，再执行 `verify.sql` 核对数量和外键。
4. 用 `npm run data:upload -- <清单> <旧站目录>` 上传 R2 文件；加 `--local` 时只写本地模拟 Bucket。
5. 测试账号登录、头像、封面、公告、资源审核与下载，再用真实大视频测试直传。
6. 上线窗口冻结旧站写入，重新导出并完成最终增量切换。

## 上线后准备

- 先邀请少量内部队员，观察登录、资料审核、R2 上传和下载。
- 在移动、联通、电信和校园网分别打开首页、图片和登录页；大陆访问速度不稳定时，再评估备案或其他加速方案。
- 在 Workers → Observability 查看错误日志，并在大批量资料导入前导出 D1 备份。
- 正式启用邮箱找回前，选择邮件服务商并补充域名发信验证。
