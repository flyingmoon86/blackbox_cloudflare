# 架构与部署

更新日期：2026-09-09。

## 已确认架构

```text
浏览器
  └─ Cloudflare TypeScript Worker（Hono）
       ├─ HTML 页面、路由、认证和权限
       ├─ Static Assets：CSS 与公开图片
       ├─ D1：账号、队员、作品、公告、审核记录和文件索引
       └─ R2：头像、剧照、剧本、音频和视频
```

前端和后端属于同一个 Worker 项目，没有独立 Pages 项目。这样只有一套部署配置、权限逻辑和日志，更适合小团队维护。

## 代码边界

- `src/routes/`：页面和表单入口。
- `src/views/` 与 `src/views.ts`：服务端生成 HTML。
- `src/auth/`：密码哈希与签名会话。
- `src/middleware/`：登录状态和安全响应头。
- `src/http/`：Cookie 与 CSRF。
- `migrations/`：只向前执行的 D1 结构变更。
- `public/`：静态文件。
- `scripts/data/`：旧 MySQL 导出、D1 转换、R2 文件迁移和虚拟验证。
- `migration-work/`：真实迁移中间文件，已被 Git 忽略。
- `legacy-python/`：迁移核对，不部署。

## 大文件方案

1. 登录用户向 Worker 申请上传任务。
2. Worker 检查队员身份、文件类型、大小和作品。
3. 正式环境由 Worker 签发 15 分钟有效的分片 URL，浏览器以 50MB 分片、最多 3 片并发直传 R2。
4. Worker 完成上传并创建 `pending` 资源记录。
5. 管理员审核后资源才进入资料库。
6. 下载时 Worker 校验权限，再提供受控下载地址。

本地没有 R2 API 凭据时，Wrangler 使用 `FILES` 本地 Bucket，分片通过本机 Worker 写入模拟 R2。正式环境设置 R2 的三个访问参数后自动切换为浏览器直传，业务页面和 D1 任务结构不变。

正式环境需要四个 Secret：`SESSION_SECRET`、`R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`。真实值只存 Cloudflare，不写进 Git、文档或聊天。`npm run r2:production:cors` 会根据正式域名生成仅允许该站点 `PUT`、暴露 `etag` 的 CORS 配置。

## 环境和上线原则

- 本地使用 Wrangler、模拟 D1、模拟 R2 和 `.dev.vars`。
- 测试环境使用独立的 Cloudflare D1/R2，不导入真实敏感数据。
- 正式密钥使用 Cloudflare Secret，不写入 Git 或 `wrangler.jsonc`。
- 全部功能、权限、大文件和数据一致性验收后才绑定域名和切换流量。
- 原 Python 网站和数据备份保留到 Cloudflare 版本稳定运行后。

## 第一次正式部署

以下命令都在 `D:\大三\blackbox_cloudflare` 的 PowerShell 中执行。

1. 登录 Cloudflare：`npx wrangler login`。
2. 确认域名已经加入同一个 Cloudflare 账号，DNS 状态为 Active。建议先使用 `blackbox.你的域名` 这样的子域名，避免影响主域名已有网站。
3. 创建数据库：`npx wrangler d1 create blackbox-production`，把输出的 `database_id` 填入 `wrangler.jsonc` 的 `env.production`。
4. 创建存储桶：`npx wrangler r2 bucket create blackbox-files-production`，把实际 Bucket 名同时填入生产环境的 `bucket_name` 和 `R2_BUCKET_NAME`。
5. 把生产环境 `routes[0].pattern` 改成最终域名，只填 `blackbox.example.com`，不带 `https://` 和路径。Custom Domain 会由 Cloudflare 创建 DNS 记录和证书。
6. 在 R2 中创建只限这个 Bucket 的“Object Read & Write”访问密钥，记下账户 ID、Access Key ID 和 Secret Access Key。
7. 在本机创建临时 `.env.production`，写入下面四项。该文件已被 Git 忽略；填写后不要把内容发到聊天：

```text
SESSION_SECRET=至少48字节的随机值
R2_ACCOUNT_ID=Cloudflare账户ID
R2_ACCESS_KEY_ID=R2访问密钥ID
R2_SECRET_ACCESS_KEY=R2访问密钥
```

PowerShell 可用以下命令生成会话密钥：

```powershell
$bytes = New-Object byte[] 48
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

8. 执行 `npm run deploy:check`。它会检查占位值、格式、类型、旧数据转换和正式构建，但不会发布。
9. 执行 `npm run db:production:migrate` 创建正式表，再执行 `npm run r2:production:cors`。
10. 一次写入四个 Secret：`npx wrangler secret bulk .env.production --env production`。成功后删除本机 `.env.production`。
11. 执行 `npm run deploy`。脚本只部署 `env.production`，不会误用本地 D1。
12. 执行 `npm run smoke:production`，再按本地验收指南用管理员和队员测试。上线后的每次数据库修改前先运行 `npm run db:production:backup`。

相关官方说明：[Workers Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)、[D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/)、[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)、[Workers Secrets](https://developers.cloudflare.com/workers/configuration/secrets/)。

## 费用估算

当前密码采用安全强度较高的 scrypt，登录和注册的 CPU 时间通常超过 Workers Free 每次 10ms 的额度，因此正式站建议使用 Workers Paid。其最低费用目前为 5 美元/月。R2 Standard 每月含 10GB，之后为 0.015 美元/GB-month；按长期保存 100GB 估算，存储约 1.35 美元/月。30 人规模下 D1 和 R2 操作量通常仍在包含额度内，因此合计可先按约 6.35 美元/月估算，另加域名、税费和汇率差异。R2 公网流量当前不收出口流量费。

价格会调整，开通前以 [Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)、[R2 定价](https://developers.cloudflare.com/r2/pricing/) 和 [D1 定价](https://developers.cloudflare.com/d1/platform/pricing/) 为准。

## 旧站数据迁移顺序

1. 给旧 MySQL 创建只读账号，运行 `npm run data:export` 生成一致性快照。
2. 运行 `npm run data:transform`，人工查看 `warnings.json`。
3. 在独立测试 D1 执行 `import.sql`，再执行 `verify.sql` 核对数量和外键。
4. 用 `npm run data:upload -- <清单> <旧站目录>` 上传 R2 文件；加 `--local` 时只写本地模拟 Bucket。
5. 测试账号登录、头像、封面、公告、资源审核与下载，再用真实大视频测试直传。
6. 上线窗口冻结旧站写入，重新导出并完成最终增量切换。

## 上线前仍需决定

- 提供实际域名，并决定使用根域名还是推荐的子域名；然后才能替换正式配置和生成精确 R2 CORS。
- 选择并开通 Workers Paid、R2，创建 D1、R2 和访问密钥。
- 邮件服务仍未确定。内部试运行可以暂不开放自助找回；正式邀请 30 名队员前，建议接入邮箱验证和密码找回，或先实现管理员重置密码流程。
- Cloudflare 部署不等同于中国大陆备案和境内加速。上线后应分别用移动、联通、电信和校园网测试；如果体验不稳定，再评估境内备案方案。
- 在 Cloudflare 安全规则中给 `/login`、`/register` 和上传任务接口设置速率限制，防止密码尝试和滥用上传。
- 在 Workers & Pages → Observability 检查日志；生产配置已开启 Workers Logs。D1 自带 Time Travel，同时仍建议重大变更前导出 SQL 备份。
