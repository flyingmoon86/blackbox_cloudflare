# 发布与恢复

## 本地检查

使用项目要求的 Node.js，首次 `npm install` 后执行 `npm run dev`。改动完成后运行 `npm run docs:check` 和相关测试；完整收口执行 `npm run deploy:check`，包含格式、类型、后端回归及生产配置构建 dry-run，不会发布。浏览器改动实际查看桌面与手机，使用合成数据；具体截图、测试数量、命令日志放任务 `artifacts/`，不累积到长期文档。

## 授权发布

推送 Git 与发布网站分别授权。正式发布仅在用户明确要求后执行：

1. 检查 Git 差异、当前域名和 `wrangler.jsonc` 绑定，运行 `npm run deploy:check`。密钥通过 Cloudflare Secret 管理，不打印或写入仓库。
2. 执行 `npm run archive:backup` 创建完整 D1 + R2 快照，核验成功并保存仓库外副本。
3. 有新增迁移时执行 `npm run db:production:migrate`，只应用增量；不要以本地整库覆盖线上。
4. 执行 `npm run deploy`。它不代替数据备份与人工授权。
5. 执行 `npm run smoke:production`，再人工检查登录/下载、上传/审核、管理员边界，以及本次涉及的功能与手机布局。冒烟不能代替完整人工验收。
6. 更新 根目录 README.md 的简短当前状态。版本号、迁移、实测结果、截图和待验证项放对应任务 artifacts；重要发布资料按下节做归档。

Cloudflare D1 导出失败、对象缺失或完整性核验未通过时，不把该快照当作可用备份。配置仍是占位值时不要发布。

## 网站数据备份与恢复

`npm run archive:backup` 默认使用正式配置，只读导出 D1、列举和下载 R2。需要现有 Wrangler 登录或具有相应读取权限的凭据。可用 `--directory` 指定备份根目录。对象按内容哈希保存，后续快照复用并重新校验；不会同步删除旧快照。

```powershell
npm run archive:verify -- --snapshot "D:\备份\snapshots\实际快照目录"
npm run archive:restore -- --snapshot "D:\备份\snapshots\实际快照目录" --target "D:\演练\全新的恢复目录"
npm run archive:drill
```

默认备份在 `migration-work/archive-backups/`，含真实数据，不提交 Git。复制备份时必须连同根目录的 `objects/` 一起复制，不能只带 `snapshots/`。仅核对数据库、文件引用、对象字节及前后清单通过后生成的 `complete.json` 才表示备份完成；未完成上传分片不在快照内。旧 `db:production:backup` 仅导出 D1，不是完整网站备份。

D1 与 R2 没有跨服务原子快照；备份时暂停人工上传/修改，工具不自动停站。隔离恢复必须使用不存在的新目标目录；恢复工具核对逐表摘要、外键、对象 SHA-256 和引用，不执行远程恢复。生产恢复需单独评估线上新增数据并制定步骤。代码回退也要确认兼容已执行迁移，不能覆盖整库或改写迁移历史。

备份至少另存仓库外，重要资料再复制到独立磁盘或受控异机位置；未实际验证异机副本时明确标记“未验证”。数据备份与下面的文档 ZIP 分开管理。

## 文档与过程资料保留

目录规则以 [AGENTS.md](../AGENTS.md) 为准。给人长期读的操作方法进 docs；可执行工具进 scripts；截图、日志、历史方案和生成中间物进 `artifacts/working/YYYY-MM-DD-任务名/`。重要资料整理前先备份，不把 Git 忽略当作可删除依据。

任务完成后，用 `scripts/preserve-artifacts.py` 将指定任务归档到仓库外；脚本拒绝秘密/数据库和符号链接，逐文件生成 SHA-256，写 ZIP 后重新读取并验证字节，生成 ZIP 校验旁文件，并更新 Git 中的 `scripts/document-archives.json`。只归档明确检查过的文档资料目录，不对 artifacts、migration-work 或整个仓库打包。

```powershell
python scripts/preserve-artifacts.py --task artifacts/archive/documents/2026-10-29-文档收敛 --backup-dir "C:\Users\gbg61\Documents\BlackboxArchives"
python scripts/preserve-artifacts.py --verify "C:\Users\gbg61\Documents\BlackboxArchives\实际文件名.zip"
```

每次生成新文件名，不覆盖旧快照。ZIP 内容包含原路径树和 manifest.json；恢复时先核验 ZIP，再解压到新的临时目录核对，不直接覆盖工作区。历史路径不作为当前规则入口。Git 中的旧已提交资料可从历史提交恢复；本地新增或忽略资料必须依靠实际验证过的 ZIP。索引仅说明已保留的位置与摘要，不意味着压缩包已上传 Git。

已完成任务按文档 documents、界面 interface、发布 releases、仓库维护 repository 移入 `artifacts/archive/分类/任务名/`。同步归档索引中的 local_directory，旧压缩包及其内部清单不重写；只增加新的位置映射。artifacts 顶层索引供本机查找，GitHub 首页统一使用根目录 README.md。
