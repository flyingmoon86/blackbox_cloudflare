# 本地验收与发布指南

## 精选照片与私密毕业去向（本地合成数据）

当前功能与权限见 [功能说明](个人精选照片与私密毕业去向.md)，最新证据见 [2026-10-27 发布验收](reviews/2026-10-27-个人档案发布验收.md)。

执行 `npm run assets:build` 后运行 `node scripts/member-records-preview.mjs`。回环地址默认 8791，`/__fixture` 可切换合成身份。禁止拿真实队员资料验收，服务关闭即丢弃数据。

1. guest、user：档案中无照片说明、编号、URL，直接 GET/HEAD/Range/条件图片请求失败，毕业去向不可读。
2. peer：只看已审核且同意队内展示的精选照片，不能修改他人照片、看去向、统计或导出；认证撤销后再次请求应被拒绝。
3. owner：在个人档案管理精选照片（照片＋可选说明），不填写“时刻”；提交待审，撤回或归档后其他队员不能看。毕业去向由独立入口维护。
4. admin：从 `/admin/member-photos` 集中查看待审队员，确认审核/撤回/归档后待审数量更新。照片审核/恢复与去向维护/年度统计分别验证。恢复照片不恢复同意；毕业去向无核实步骤，保存直接进入统计。验证保研率不再依赖旧 verified 列，历史未知/拒绝/缺失仍排除于分母。核对版本冲突、历史与最小 CSV。
5. 毕业去向逐项切换保研、考研、出国/境、就业、创业、其他、还没定，确认只显示对应字段；无 JS 提交也只保存当前类型的答案。旧本科/博士/来源字段保留，类型切换的旧答案保留于历史。
6. 桌面 1366×768、手机 390px 实际检查照片页签、放大、键盘/Esc/焦点返回、表单、触屏、减少动画及无 JS 回退。不得用自动化 HTTP 结果代替浏览器实测。

专项：`node --test scripts/backend/member-records.test.mjs scripts/backend/member-photos.test.mjs scripts/backend/runtime.test.mjs`。最终 `npm run deploy:check`（不部署）。增量迁移 0025、0026、0027 不改写；发布时应依序迁移并发布兼容代码，不能以旧公开照片草案回滚代码。旧内部照片不自动转入精选照片。

> 详细发布操作手册。README 只给了命令顺序，本文解释**每一步检查什么、验收什么、失败怎么办**。
> 发布的事实结果（哪天验证过什么）记在 [验证记录](验证记录.md)，不记在这里。

## 加载与作品浏览专项（只读合成数据）

客户端模块在 `src/client/` 维护，运行检查前先 `npm run assets:build`；`public/curtain-boot.js`、`navigation-preload.js`、`work-browse.js` 是生成入口，不手改。开发监听、页面与档案扩展入口见 [代码结构与维护](代码结构与维护.md)。

首次幕布视觉验收：`node scripts/check-curtain-visual.mjs`。使用当前源码和本地绒布纹理，覆盖桌面/手机、图片失败/慢请求、准备脚本失败、减少动画。截图和计时输出到 `.wrangler/evidence/curtain-visual-v2/`；45% 半开截图为暂停动画采样，真实清理时间另行不暂停测量。记录见 [首次揭幕视觉重做](reviews/2026-10-15-首次揭幕视觉重做.md)。

先执行 `npm run assets:build`，再运行 `node scripts/check-loading-performance.mjs --label=after`。脚本使用本机 Edge，分别测量 1366×768、390×844、弱网加 CPU 限速，输出到 `.wrangler/evidence/2026-10-15/loading/<label>/`；不连接线上数据库或文件桶。

作品渐进封面、返回列表、键盘/触摸和失败回退：`node scripts/check-loading-performance.mjs --mode=interactions --label=work-browse`。Playwright 不在默认 bundled 路径时通过 `--playwright=<模块绝对路径>` 指定。

作品浏览检查同时覆盖普通与叠图卡片：手机尚未悬停或聚焦时，简介和操作区应可见且可点击。导航取消、页面恢复、离线/省流切换的任务取消与恢复另由 `scripts/backend/navigation-preload.test.mjs` 覆盖。

历史 `check-navigation-loading.mjs`、`check-navigation-light.mjs` 现在转接当前导航检查，历史 `--serve-delay` 参数已退役。重跑旧报告需使用其对应旧提交，不能用旧转场断言验收当前版本。

首次加载与站内直切回归运行 `node scripts/check-work-curtain-browser.mjs`。默认使用本机 bundled Playwright / Edge，输出到 cloudflare 内的 `.wrangler/evidence/native-navigation`；可设置 `PLAYWRIGHT_MODULE`、`EVIDENCE_DIR`。先断言首次冷加载只有一个幕布，然后持续监测站内源页/目标页幕布插入次数为 0，不能只在动画结束后检查。原生请求时长及大图完成时长分别记录，不能把普通网络响应时间算成脚本延迟。当前行为见 [站内直接切换修正](reviews/2026-10-15-站内直接切换修正.md)。

对照前版本只允许使用改动前已冻结且带哈希的快照，不能拿修改后的当前目录重建基线。报告需注明合成数据、实际浏览器版本、网络/CPU 条件、截图是否查看，以及真机/生产未验证项。样例见 [2026-10-15 验收记录](reviews/2026-10-15-加载与作品浏览验收.md)。

## 一、发布前准备

### 公告 Markdown 专项

运行 `npm run assets:build`，再执行 `node --test scripts/backend/announcement.test.mjs`，检查正文排版、纯文本换行、链接与 HTML 过滤、权限和长度边界。

浏览器验收可用 `node scripts/announcement-preview.mjs`，打开输出的本地地址。该服务仅绑定回环地址，使用内存数据库和合成管理员，只在测试服务内给公告路由及通知读取注入测试会话，不读取或修改本地真实账号、生产数据。关闭进程即丢弃合成公告。

按桌面 1366×768 / 手机 390px 检查输入 Markdown、选区加粗、插入链接（Enter 确认、Esc 取消）、富文本粘贴保留地址、预览、实际发布后点击入口、长文本与表格溢出。给编辑页追加 `?editor-script=off` 可移除该页编辑脚本，验证原生表单仍能发布；这不等于关闭全部 JavaScript。额外的全局无脚本、真机触屏及减少动画验收应分别记录。

日常发布：标题填在标题栏；正文可用 `## 小标题`、`**加粗**`、`- 列表`、`[注册账号](/register)`。点击“预览公告”确认后发布。站内 `/` 路径在后台预览和阅读时也指向配置中的主站；预览链接另开标签避免丢稿。可直接使用 [4.0 公告源文](releases/v4.0-公告.md)，第一行用作标题，其余复制到正文。

已有公告的数据不迁移，普通文字与换行仍可读；原文若包含 Markdown 语法会按新规则排版。粘贴时已丢失地址的文字无法自动恢复链接，需重新提供地址。正文最多 20,000 字符；HTML 按文字显示，图片不嵌入。

### 环境要求

- Node.js 24 或更新版本
- Cloudflare 账号权限（能操作 Worker、D1、R2）
- 生产环境的 Secret 已配置：`SESSION_SECRET`（必需）、`TURNSTILE_SECRET`（Turnstile 开启时必需）
  - 仓库只声明需要哪些密钥，**不保存密钥内容**。Secret 与 Turnstile 密钥分开，不能互相替换。

### 发布前自问

1. 有没有数据库迁移要执行？（`migrations/` 编号是否比生产已应用的更大）
2. 上一次完整备份是否校验成功？（`migration-work/archive-backups/`）
3. 这次改动影响哪些流程？（浏览 / 上传 / 审核 / 导入 / 登录——验收时要覆盖到）

## 二、发布流程（逐步说明）

### 第 1 步：`npm run deploy:check`

**做什么**：格式检查 → 类型检查 → 后端测试 → 生产构建干跑。

**这一步不会发布任何东西**，失败也不会影响线上。

| 失败在哪 | 怎么办 |
| --- | --- |
| 格式检查 | `npm run format` 后重试 |
| 类型检查 | 修 TypeScript 报错 |
| 后端测试 | `npm run test:backend` 单独跑，看具体用例 |
| 构建干跑 | 看报错定位到 `src/` 或配置问题 |

配置检查还会核对：正式域名、D1 database_id、R2 桶名是否仍是占位值，主站与后台域名是否不同，必需 Secret 是否已声明、正式上传模式是否明确配置。占位值未填写时**不会部署**。

### 第 2 步：`npm run archive:backup`

**做什么**：导出生产 D1、增量保存 R2 文件，校验数据库引用与文件内容。默认保存在 `migration-work/archive-backups/`；成功必须生成 `complete.json`，认证失败或缺文件不能跳过。

恢复演练使用 `npm run archive:restore -- --snapshot <快照目录> --target <新的本地目录>`。复制备份时同时保留 `objects/` 与 `snapshots/`，并另存到独立存储。详细步骤与边界见 [备份恢复](备份恢复.md)。旧 `db:production:backup` 仅导出 D1，不能替代此步骤。

### 第 3 步：`npm run db:production:migrate`

**做什么**：对生产数据库应用 `migrations/` 中尚未执行的迁移。

**注意**：

- **本地数据库更新不会自动更新生产。**
- 没有新迁移时这步是空操作，可以直接跳过。
- 不要修改已执行过的迁移文件。新增结构用新的编号文件，默认向后兼容（加列不删列）。
- 迁移失败时先看报错，**不要重复执行不明确的语句**；必要时用第 2 步的备份评估影响。

### 第 4 步：`npm run deploy`

**做什么**：发布 Worker 到生产（`wrangler deploy --env production`）。

**注意**：

- **`git push` 不会触发发布**，发布只由这条命令产生。
- 部署前 `assets:build` 会自动重建静态资源产物。

### 第 5 步：`npm run smoke:production`

**做什么**：请求生产站点的 9 个公开地址，核对状态码和内容类型：

| 检查 | 地址 | 期望 |
| --- | --- | --- |
| 首页 | `/` | 200 HTML |
| 健康检查 | `/health` | 200 JSON 且 `ok` |
| 静态样式 | `/app.css` | 200 CSS |
| 作品公开浏览 | `/productions` | 200 HTML |
| 公告公开浏览 | `/announcements` | 200 HTML |
| 队员公开浏览 | `/members` | 200 HTML |
| 资料公开浏览 | `/resources` | 200 HTML |
| 鸣谢 | `/thanks` | 200 HTML |
| 后台保护 | `/admin` | 302（未登录被拦） |

**能力边界**：只能发现公开页面或接口的明显故障。**不能代替人工验收。**

## 三、发布后人工验收清单

冒烟通过后，实际登录点一遍（生产验证不能只看脚本结果）：

- [ ] 访客浏览作品详情、资源预览正常
- [ ] 登录 → 下载一个已批准资源
- [ ] 登录 → 上传一个测试资料（走完分片 → 合并 → 记录建立）
- [ ] 管理员审核该资料（批准 / 驳回各试一次）
- [ ] 管理员后台入口：普通账号进不去，管理员能进
- [ ] 如有迁移涉及演职：批量导入一次（或用预览走一遍）
- [ ] 手机宽度（390px）关键页面不破版

## 四、回滚

1. **代码问题**：用 wrangler 重新部署上一个版本（Cloudflare 保留部署历史）。
2. **迁移问题**：迁移通常没有自动回滚。先用备份评估影响范围，再决定补一个反向迁移还是手工修复数据。**不要用本地整库覆盖线上**（本地是独立快照，线上可能已有新数据）。
3. **数据问题**：先校验最近完整快照，再恢复到隔离环境核对数据和文件；评估线上新增数据后单独制定恢复步骤，见 [备份恢复](备份恢复.md)。

## 五、本地验收（改动不上线时）

改完代码、准备提交前：

```bash
npm run format          # 格式化
npm run typecheck       # 类型
npm run test:backend    # 后端测试
npm run deploy:check    # 全套（含构建干跑）
```

涉及页面视觉的改动，本地 `npm run dev` 后在浏览器实际检查 1366×768 与 390px 两种宽度，键盘和触屏可操作，减少动画模式不丢功能。

## 六、日常维护事项

| 事项 | 频率 | 说明 |
| --- | --- | --- |
| 检查清理任务是否在跑 | 每次发布后 | 系统页查看积压、最老任务年龄及最近成功时间 |
| 查看备份 | 每次发布前 | 完整快照校验成功，保留独立副本 |
| R2 文件备份 | 每次发布前及资料更新后 | `archive:backup` 增量保存，验证完成标记 |
| 恢复演练 | 改动备份/迁移流程后 | 样本演练已通过；正式数据演练需先解决 D1 导出认证错误 |
| 权限 / 上传 / 导入线上验收 | 发布后 | 用第三节清单 |
