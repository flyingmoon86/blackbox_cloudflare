本轮前端改版、清晰封面与背景、作品搜索、工作台精简、持续待办及公告一次性提示已发布到 https://npublackbox.online/ 和 https://admin.npublackbox.online/。Worker 版本：9523c8da-72bb-4f57-9f2c-80f85fac8b58。69 项测试及线上页面/封面/后台保护检查通过；登录后的提醒交互、手机视觉请按下面步骤人工验收。线上无待执行迁移，本次仅发布代码和静态资源。


- 管理员任务提醒：有任务时工作台顶部显示醒目横幅，页头持续显示待办总数。点过通知的“处理”但没有完成审核，刷新后总数仍保留；实际处理后自动重新核对，无待办时隐藏。页面可见时约每 60 秒检查，后台标签暂停；网络失败不应清空已有提示。

- 管理员工作台：原三个大卡片改为待处理横栏、常用管理分组和默认折叠的更多管理。核对五类待办数量与跳转、创建作品/新建档案入口、审核历史/系统状态展开，以及手机两列布局；账号管理与队员审核保留。

## 延迟与 Turnstile（2026-09-14 已发布，真实挑战验收待确认）

- 审核成功现在局部移除条目并定位下一条，按钮显示“处理中”。网络失败保留说明并提示先刷新核对，不自动重试写入；无脚本仍使用原表单。旧通知计数改为“查看最新待办”，避免再发一次通知查询。
- 开发者工具 Network 中查看动态响应的 `Server-Timing: worker;dur=...`，这是服务端处理总时间（包括后端等待），不是纯 CPU 时间，也不是数据库独立耗时。结合请求 TTFB 判断，不将两者差值简单当作精确网络延迟。
- 首页独立查询并行，静态指纹资源继续长期缓存，账号/后台/待审响应继续 private,no-store。没有给全站添加 Cache Everything。
- Smart Placement 已以 placement.mode=smart 开启；初期响应仍为 local-LAX/local-SJC，尚无转移位置的收益证据。后续需同网络、多时段继续比较，不能把刚启用时的样本当作最终结果。它不能保证改善大陆跨境网络，免费计划可用也不等于必然更快。
- Turnstile 已开启注册与未登录网站建议，登录和管理员审核不增加验证。`TURNSTILE_ENABLED` 当前为 true；`TURNSTILE_SITE_KEY` 是公开站点标识，Secret 不进 Git。线上已确认无效 token 返回 403，真实挑战成功与重放验收仍待完成。
- Cloudflare 正式 Worker 的 Settings → Variables and Secrets 另外新增 **Secret 类型 TURNSTILE_SECRET**，值来自该组件的 Secret Key；**不能覆盖 SESSION_SECRET**。确认组件允许 npublackbox.online。
- 当前 production.secrets.required 已含 TURNSTILE_SECRET，线上绑定名称已确认。真实验收仍必须取得新 token，成功提交一次、重放拒绝；当前模拟回归和线上无效令牌检查通过，不能声称真实浏览器端到端验收完成。出现真实用户无法验证时，应先排查组件域名、密钥匹配和网络。
- 本地测试用 Cloudflare 官方测试密钥与单独的 localhost/127.0.0.1 allowlist；不得把本地域名加入生产 TURNSTILE_HOSTNAMES。失败时重新打开页面获取新验证；Token 不记录到日志。

参考：[Smart Placement](https://developers.cloudflare.com/workers/configuration/placement/)、[Turnstile 服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。

## 审核操作优化（2026-09-14，本地完成，尚未部署）

适用于队员认证、作品加入、资料审核。运行 `npm run dev`，以管理员登录后验收：

1. 输入搜索关键词并选择类别，刷新或重新进入，筛选仍保留。同一浏览器按账号和审核页面分别记忆，不跨设备同步；点“清除筛选”恢复全部。
2. 选择常用驳回理由，说明框应填入可编辑文字，原有文字保留；此时不能自动提交。空理由驳回应被拦截，随后仍可选择通过。
3. 明确点击通过或驳回，成功返回后应定位当前筛选内下一条；失败、仍在待办中的条目不能触发自动跳过。
4. 当前类别全部处理后显示提示，可清除筛选查看其他类别。无匹配结果时也可清除；修改筛选后旧定位提示消失。
5. 手机检查搜索、类别、理由和操作按钮可滚动到达，没有横向溢出。禁用脚本时原审核表单仍能使用，权限和 CSRF 仍由服务端检查。

筛选保存在本机浏览器；审核说明不保存到浏览器存储。请勿在生产环境用真实申请练习驳回。

## 独立后台使用与验收

正式后台：[admin.npublackbox.online](https://admin.npublackbox.online/)。使用现有管理员账号，首次在此地址登录；主站与后台登录状态独立，最长 14 天，共用设备结束后从账号页退出。

- 顶栏或手机底栏点“工作台”即可返回；作品、队员和资料在后台内管理。“查看正式网站”另开标签，不丢当前编辑页面。
- 工作台待办带数量提示，点击对应类别处理；账号管理在下方折叠区展开。没有取消删除确认或修改权限校验。
- 未登录打开后台管理页应回后台登录，并保留目标地址；普通账号即使密码正确也不能进入；退出后再开管理页应重新要求登录。
- 主站旧 /admin 页面应跳转新域名。主站公开浏览仍正常；旧页面尚未提交的合法管理表单保留权限校验，兼容当前操作。
- 本地默认 `npm run dev` 仍保持单地址。验收双入口可运行：

```powershell
npm run dev -- --var ADMIN_ORIGIN:http://127.0.0.1:8787 --var PUBLIC_ORIGIN:http://localhost:8787
```

此时 localhost:8787 为本地主站，127.0.0.1:8787 为本地后台，共用本地数据。无需修改正式 DNS，无需复制线上库。改回普通开发时停止进程，再运行 `npm run dev`。

## 作品多版本验收

1. 管理员进入“作品档案 → 创建作品”，填写首个版本名称与年份，点击“添加一个版本”继续填写。可以同年不同版本，但不能同年同名。保存后列表只出现一张作品卡。
2. 进入作品，版本按年份从新到旧排列；上方版本链接跳到对应区域。管理员可展开“编辑这个版本”修改名称、年份和介绍，也可在页面底部继续添加版本。
3. 添加演职员或队员提交“我是主创”时必须选择版本。同一角色在不同版本独立保存；同一版本允许多人饰演，也允许一人申请多个角色。完全相同的记录不能重复提交。
4. 队员填写已有角色时切换版本，人数提示只计算当前版本。审核页和队员的申请状态都显示版本，批准后进入所选版本的名单。
5. 点击某一版本的“补充这个版本的资料”，上传页应自动选中作品和版本；改选另一部作品后，旧版本被清除。作品资料必须选版本，管理员可移动同作品其他版本的资料。
6. 旧作品各生成一个原年份的“初始版本”，旧演职员与待审核申请归入其中；旧文件保持原路径，未分版本的作品资料归入默认版本，已选版本保持不变。年份未知时显示“年份待补”，不猜测历史版本。
7. 作品卡按最新版本年份排序，精选仍排第一。检查电脑 1366×768 和手机 390px，多个版本表单、演员表和剧照均可阅读、滚动。

## 手动发布

只在确认发布时执行，Git 推送不触发部署。使用项目脚本选择 production，不能直接运行缺少环境参数的 `npx wrangler deploy`。

```powershell
npm run deploy:check
npm run db:production:backup
# 仅存在尚未应用的迁移时执行
npm run db:production:migrate
npm run deploy
npm run smoke:production
```

备份保存到不进 Git 的 `migration-work/backups/`，包含私有数据。发布前后核对作品、档案、账号、资料及文件；只上传代码和增量迁移，不能导入本地整库覆盖生产。D1 备份不包含 R2 文件字节。

Cloudflare 登录失效时用 `node scripts/wrangler.mjs login`；此脚本修正形如 Markdown 链接的代理环境变量，避免 `Invalid URL`。不要发送密码或密钥到聊天里。

部署失败先看实际错误与当前服务版本，不删除数据库或 Worker。存在多版本数据后，不直接回退到不理解 `edition_id` 的旧代码；应发布兼容修复。数据库恢复会影响备份之后的数据，必须单独评估。

## 启动

在 blackbox_cloudflare 文件夹打开 PowerShell：

```powershell
npm ci
# 首次使用且没有 .dev.vars 时：
Copy-Item .dev.vars.example .dev.vars

不要覆盖已有 .dev.vars，不删除 .wrangler 数据库。浏览器打开 http://127.0.0.1:8787 。本机已有 2026-09-13 线上快照，可用同步时的账号登录；后续不是自动同步。以下提升测试管理员的命令仅供没有账号的新电脑使用。

node scripts/wrangler.mjs d1 execute blackbox-local --local --command "UPDATE user SET role='admin' WHERE username='你刚注册的本地测试用户名'"
```

## 本轮逐项检查

Version 1.0 后续修正：PC 首页第二幕不允许内部滚动，海报占满右侧可用高度。鼠标移到正文或海报区域，向上滚轮应直接回第一幕；长介绍通过“阅读完整介绍”弹窗查看。认证档案按入学年份降序分组（缺少年级时用入队年份）。PC 横版作品两列、竖版最多三列，横图保持图片比例。

1. **资料库与作品**：PC 可以上下滑动；作品一页最多 12 部，资料一页最多 24 条。照片完整可见，不再被压成细条。翻页和搜索能找到后面的内容，其他资料排在作品后。作品内资料也可翻页。
2. **作品主题**：管理员→作品编辑→作品主题色，输入 HEX 或用色盘，保存后进入详情页。留空保存恢复全站色；其他作品不受影响。
3. **首页第一幕**：标题下没有重复欢迎语；精选大戏可有可无，左下有公告；导航含图标、账号图标直接点击。
4. **首页第二幕**：点击“探索剧团”；没有“关于我们”“加入舞台”小标题，只有正文。大标题可在页面管理修改，显示时去标点。PC 海报完整放大利用右侧，手机自然下滑，海报可点击放大。
5. **页面管理**：仅保留首页图片、精选大戏、第二幕正文、海报、邮箱/QQ群、颜色、测试须知和两份指南。微信/公众号/重复欢迎语等入口不再出现。
6. **选图**：背景、小象、作品封面、海报均使用“备选图片”。点开见缩略图；选择后显示当前图，取消/Esc 不改变选择；空选项可清除。手机也能操作。
7. **认证**：普通账号→申请队员认证，先找已有档案；点“找不到我的档案，申请新建”才显示新建表单；该页不出现已有档案下拉。可返回重新选择。
8. **个人信息**：没有“代表作”输入，已关联的作品自动显示在公开档案。更换头像后应正常显示；新图生成小展示版，旧头像仍能看。
9. **年份**：作品、建档申请、队员档案和筛选选项为 2026—2020。历史 2019 等年份编辑其他字段后不被清空。
10. **手机与键盘**：390px/360px，无横向溢出；底栏不遮住保存按钮。Tab 可操作导航、图片和表单，Esc 可关选图；减少动画下仍可切首页。

## 必须保持的权限

- 游客能浏览公开资料低清图，不能取原件、查看待审资料或进入后台。
- 普通账号可上传，人工审核；认证队员低风险资料直接入库，可疑资料转人工。
- 视频选择时提示测试阶段不支持，不能绕过前端从接口上传。
- 作品 AB 角和一人多角不互相覆盖；删作品后资料转其他资料。
- 管理员改色/选图/审核须检查 CSRF 和权限；旧账号密码仍可用。
