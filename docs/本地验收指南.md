# 本地验收指南（第一次运行）

这套步骤只在你的电脑上启动测试网站，不会发布到互联网，也不会连接正式数据库。正式站点验收命令见文末；生产试运行使用 Workers Free 和 R2 免费额度，视频上传已暂停。

## 一、打开项目终端

在资源管理器打开：

```text
D:\大三\blackbox_cloudflare
```

在文件夹空白处右键，选择“在终端中打开”。确认终端提示符最后是 `blackbox_cloudflare>`。

## 二、第一次准备

依次复制并执行：

```powershell
npm install
Copy-Item .dev.vars.example .dev.vars
npm run db:init
```

如果提示 `.dev.vars` 已存在，可以跳过第二条。这个文件只保存本机测试密钥，不会上传 GitHub。

## 三、启动网站

执行：

```powershell
npm run dev
```

看到类似下面的文字即表示启动成功：

```text
Ready on http://127.0.0.1:8787
```

按住 `Ctrl` 点击该网址，或复制到浏览器打开。测试期间不要关闭这个终端。

## 四、按顺序检查

1. 未登录首页先显示“测试须知”；确认后看到“这里是黑匣子”、登录和注册入口。
2. 点击“注册”，创建一个测试账号。密码需要 8–128 位。
3. 用刚注册的账号登录，首页应显示“欢迎回来”。
4. 打开“个人中心”，确认用户名、身份和邮箱状态正确。
5. 先故意输入错误的当前密码，网站应拒绝修改。
6. 再输入正确的当前密码并设置新密码，网站应回到登录页。
7. 旧密码应无法登录，新密码应可以登录。
8. 在个人中心点击“退出登录”，应回到未登录首页。

测试账号只存在于本机 D1 模拟库，不会出现在 GitHub 或未来正式网站。

## 五、停止网站

回到运行网站的终端，按：

```text
Ctrl + C
```

## 六、只检查代码能否构建

不打开网站时，可执行：

```powershell
npm run typecheck
npm run build
```

两条命令都无报错，表示 TypeScript 类型检查和 Cloudflare 模拟打包通过。`npm run build` 不会发布网站。

## 七、代理地址错误

项目的 npm 命令会自动把误写成 Markdown 链接的代理变量还原为纯网址。如果升级依赖后再次看到 `TypeError: Invalid URL`，请先确认运行的是最新版代码，再执行 `npm run dev`。

## 八、验收管理员审核

1. 用普通测试账号提交一条队员认证申请。
2. 使用管理员账号进入“管理员工作台”，分别测试通过和驳回；驳回时必须填写理由。
3. 申请人重新登录后，应在个人中心看到结果。
4. 管理员可禁用其他测试账号，但不能禁用自己。
5. 在“账号管理”找到已认证队员，展开“解绑档案”，勾选确认后解绑；该账号应立即退出登录并变回普通用户，原队员档案、作品演职员记录和资料仍应保留。
6. 解绑时该账号尚未审核的作品加入申请应一并取消；管理员账号、普通账号和未勾选确认的操作都必须被拒绝。

## 九、验收作品与演职员

1. 管理员打开“作品与资料”，点击“创建作品”。
2. 填写名称、年份、短介绍和剧情介绍并保存。
3. 在作品详情中从队员下拉列表选择人员，分别添加演员角色和后台分工。
4. 确认两类人员分组显示，并可点击姓名进入队员档案。
5. 编辑作品标题或介绍并保存。
6. 用普通账号登录，确认可以查看作品，但看不到编辑和删除操作。
7. 给该作品提交剧本、剧照或音频并由管理员审核通过，返回作品详情后，应在“相关资料”中看到资料并能打开详情。
8. 待审核或已驳回的资料不应出现在作品详情的“相关资料”中。
9. 用认证队员在作品详情选择“演员”或“后台与创作”，填写角色或分工并提交加入申请。
10. 管理员从工作台进入“作品加入审核”，通过后该队员和分工应出现在作品演职员名单；驳回时必须填写理由。
11. 管理员创建或编辑作品时，应能勾选未归类的待审核和已入库资料；待审核资料即使关联后也不能提前显示给普通用户。
12. 给两个作品分别选择已审核剧照作为封面，并把封面比例分别设为“横版”和“竖版”；回到作品档案列表，横版图应按 16:9 展示，竖版图应按 3:4 展示，进入详情后比例仍保持一致。
13. “作品与资料”打开后应停在“作品档案”标签；点击“资料库”可直接切换，当前标签以黄色高亮显示。
14. 从作品详情可以一键返回作品档案或前往资料库；从资料详情和上传资料页也能返回资料库或作品档案。
15. 用认证队员打开作品档案，每张作品卡片底部应显示“我是主创！”和“我要补充资料！”；前者跳到该作品的角色或分工申请，后者打开上传页并自动选中该作品。
16. 用未认证的普通账号打开作品档案，不应显示上述两个队员操作按钮，只显示“认证为队员后……”入口；直接打开上传地址也应被拒绝并提示先申请队员认证。
17. 用认证队员打开作品档案，页面标题旁应显示“申请创建作品”；提交后返回作品档案，管理员能在“建议与建档申请”中看到结构化作品名和年份。
18. 先让管理员给甲队员登记“演员 · 哈姆雷特”，再让乙队员申请相同角色；输入相同名称时页面应提示已有人员，管理员审核页应显示甲队员且说明通过不会覆盖。
19. 管理员通过乙队员申请后，作品名单应按“哈姆雷特”归组，同时显示两人和“多人饰演 / AB角”标记。
20. 乙队员继续申请另一个演员角色和一项后台分工，两条都应能提交；完全相同的队员、类别和角色重复提交应被拦截。

## 十、验收公告与首页

1. 管理员进入“管理员工作台”，点击“管理公告”并发布一条测试公告。
2. 回到登录后首页，确认公告入口出现在首页内容中，顶部导航没有“公告”。
3. 退出登录后直接打开 `/announcements`，应先跳到登录页面。
4. 管理员进入“页面管理”，编辑首页欢迎语、剧团介绍和联系说明。
5. 从已有作品中指定一部带封面的“精选大戏”并保存。
6. 编辑该作品，把首页布局设为“图文并列”，确认首页封面和介绍左右排列；再设为“文字叠加”，确认文字显示在带渐变遮罩的大图上。两种布局应有明显区别。
7. 分别把该作品封面比例设为“横版”和“竖版”，确认首页精选区会随之变成宽幅或竖幅构图，并始终显示所选封面。
8. 退出登录，确认紧凑首屏同时显示欢迎区和精选大戏，并保留带封面的精选大戏。
9. 未登录点击精选大戏，应先登录；登录后进入对应作品。
10. 管理员登录首页，点击文案旁的编辑入口，应跳到页面管理的相应位置。
11. 登录首页的公告和“第一次使用网站？”应使用统一卡片样式；“查看网站使用指南”和“提交网站建议”都位于首次使用卡片底部。
12. 普通账号显示“这里是黑匣子”，认证队员和管理员显示“黑匣子永远是你的家”；管理员可分别编辑两类欢迎语。
13. 管理员修改测试须知后，在浏览器重新打开首页应再次弹出；不修改内容时，确认一次后不重复弹出。
14. 认证队员从“第一次使用网站？”进入意见箱提交建议，管理员从工作台进入建议收件箱并标记已处理。
15. 招新、关于我们和联系剧团应合在同一张卡片中，电脑端横向三列、手机端纵向排列；联系区只显示邮箱和已配置的 QQ 群，不显示微信或公众号。
16. 联系区直接显示邮箱文字链接和已配置的 QQ 群，不再放置复制邮箱按钮。
17. 全站应使用炭黑、暖白和舞台朱红配色；按钮悬停或键盘聚焦时有清晰反馈，原黄褐色视觉不再作为主色。

## 十一、验收资料提交与审核

1. 用已认证队员账号进入“作品与资料”，点击“提交资料”。
2. 填写标题、类型、所属作品或“其他资料”、原文件名和说明并提交。
3. 打开“我的提交”，确认状态显示“等待审核”；此时该资料不应出现在公共资料库。
4. 用未认证普通账号直接打开 `/resources/submit`，应看到完整的认证说明页和申请认证按钮。
5. 管理员进入“管理员工作台”，点击“审核资料”。
6. 尝试不填理由直接驳回，网站应拒绝；填写理由后可正常驳回。
7. 队员在“我的提交”中应看到“已驳回”和管理员理由。
8. 再提交一条资料并由管理员通过，确认它出现在资料库并可进入详情页。
9. 详情页应提示文件已经保存但等待审核；审核通过后显示“下载文件”。
10. 类型选择“剧照”后，一次选择多张图片；完成后“我的提交”中每张剧照都应有独立的待审核记录。
11. 管理员可逐张通过或驳回；资料库按作品显示，每部作品只有一块剧照集卡片，内部排列该作品的全部已入库剧照。
12. 从作品卡片点击“我要补充资料！”，上传页的“所属作品”应自动选中刚才的作品。
13. 如果下拉列表里没有对应作品，点击“申请管理员新建作品档案”，填写作品名称、可选年份和补充说明后提交。
14. 管理员从工作台进入“建议与建档申请”，应看到“作品建档申请”标记、作品名、年份、申请人和补充说明；处理后可标记为已处理。
15. 在资料库确认所有作品分组排在“其他资料”之前；作品之间按年份和建档顺序排列，“其他资料”始终位于最后。
16. 同一作品先后加入两份普通资料，较晚提交的卡片应在前；剧照集内部也应按最新提交在前。
17. 搜索资料标题、说明或原文件名，应只显示匹配资料；搜索作品名，应显示该作品下的全部匹配分组资料。
18. 搜索不存在的内容，应明确显示“没有找到”；输入 `%` 或 `_` 时应按普通字符搜索，不能错误地返回全部资料。点击“清除”恢复完整资料库。

## 十二、验收队员档案与帮助页

1. 用已认证队员账号打开“个人中心”，点击“修改我的信息”。
2. 修改个人简介和代表作并保存；姓名、年份和届别不应出现在队员自助表单中。
3. 返回自己的队员详情，确认新内容和“编辑我的简介与代表作”入口都存在。
4. 用管理员打开任一队员详情，点击“编辑队员档案”，确认管理员可修改姓名、年份、届别、简介和代表作。
5. 普通登录用户从个人中心进入“使用指南”，只能看到队员指南。
6. 管理员进入“使用指南”，应同时看到队员指南和管理员指南。
7. 管理员点击指南旁的编辑入口，应直接跳到“页面管理”的对应输入框。
8. 修改两份指南并保存，再分别用普通账号和管理员账号检查可见范围。
9. 指南顶部应能跳到“寻找作品、登记演职员、上传资料、个人档案”等位置，每块都有可直接打开相应页面的入口。
10. 普通队员应看到固定操作步骤和管理员编辑的队员须知，但看不到“队长与管理员指南”。
11. 管理员应额外看到审核演职员、审核资料、处理建档申请、创建作品、发布公告和页面管理快捷入口。
12. 修改管理员自定义指南后，固定操作步骤仍应保留，避免误删文字后整份指南失效。
13. 管理员在队员名录点击“新建队员档案”，填写姓名、年份、届别、简介和代表作后建立档案；新档案应能被以后注册的账号申请绑定。

## 十二点二、验收队员剧照卡与账号删除

1. 打开队员名录，确认有头像的队员以头像铺满整张卡片；没有头像时显示姓名首字的舞台色占位，不出现破图。
2. 电脑上把鼠标移入队员卡片，头像应快速放大并虚化，简介、花朵数量和“查看档案”从下方滑入；移开后恢复。
3. 用键盘 Tab 聚焦卡片，应得到与鼠标移入相同的完整信息；点击卡片任意位置都能进入队员档案。
4. 手机端没有悬停，因此简介与查看入口应始终可见，卡片仍保持单列且不横向溢出。
5. 管理员工作台的账号列表中，展开“删除账号”，必须输入完整用户名才能删除。已删除账号不能再登录，相关队员档案和已审核资料仍保留。
6. 管理员尝试删除自己应得到拒绝；系统仅剩一名管理员时也不能删除该管理员；仍有进行中大文件上传的账号应先处理上传任务。

## 十二点一、验收管理员待办与作品删除

1. 分别准备一条待审核队员认证、作品加入、资料、作品建档和网站建议；管理员打开任意登录页面，顶部应出现带总数的“待处理”。
2. 通知下拉最多展开 4 类并轻微错位堆叠；超过 4 类时只显示一行剩余数量，通知块不能无限向下延伸。
3. 点击一条通知的“处理”，应记住当前管理员已读状态并跳到对应审核页；返回其他页面后，该通知不再显示。另一位管理员仍应看到自己的未读通知。
4. 新的同类申请到来后，即使旧通知已读，也应再次显示新通知。
5. 管理员工作台顶部应按“待处理、内容管理、网站设置”分组，待办入口显示数量；“新建队员档案”和“创建作品”都能直接进入。
6. 新建一部测试作品并关联一份资料，在编辑页底部输入完整作品名后删除。作品和演职员关系应消失，关联资料应保留并进入资料库的“其他资料”。
7. 输入错误作品名时删除必须被拒绝；未登录者和非管理员不能调用删除接口。

## 十三、验收 R2 文件与图片

拉取本次更新后先执行一次：

```powershell
npm run db:init
```

这会应用新的上传分片表。然后启动网站并按以下顺序检查：

1. 已认证队员打开“上传资料”，选择一个本地测试文件并开始上传。
2. 上传进度应增长，完成后进入资料详情，状态为“等待审核”。
3. 可用较大文件测试断点续传：上传一部分后关闭页面，重新进入并选择同一个文件，应提示继续上次任务并跳过完成的分片。
4. 上传过程中点击“取消上传”，页面应显示“上传已取消”。
5. 管理员审核通过后，详情页出现下载按钮；视频播放器或下载工具请求文件片段时支持 Range。
6. 管理员从工作台进入“管理资料”，可修改标题、类型、归属作品和说明，也可删除文件。
7. 队员在“修改我的信息”中上传 JPG、PNG、WebP 或 AVIF 头像；伪造格式和超过 15MB 的图片应被拒绝。
8. 管理员编辑作品时，只能从该作品审核通过的剧照中选择封面。
9. 管理员在“页面管理”中可分别选择“首页首屏剧照”和“全站模糊背景剧照”；后者应出现在首页、表单和管理页的暖白半透明底层，不能影响文字可读性。
10. 删除正被用作封面、首页首屏或全站背景的剧照后，对应引用应自动清除。
11. 首页标题以“黑匣子”开头时应在其后换行；首屏右上应显示戴眼镜的毛绒小象照片，并带“后台留影”标记。
12. 招新、关于我们和联系剧团应呈现为紧凑深色页尾；联系区只保留邮箱文字链接和已配置的 QQ 群，不显示“写邮件”或“复制邮箱”按钮。

本地环境使用 Wrangler 模拟 R2，不会占用云端空间。本轮待发布版本经 Worker 绑定 R2 逐片上传，分片不超过 50MB；不启用 S3 并发直传。

## 十四、验收资料卡片与详情预览

拉取本次更新后先执行一次 `npm run db:init`，让本地数据库增加预览图字段。

1. 分别上传一张图片、一个剧本和一个音频文件，并由管理员审核通过。视频预览只使用已有视频或隔离测试夹具验收，不开启新视频上传；没有视频样本时跳过视频播放检查。
2. 打开“资料库”，图片卡片应以低画质缩略图作背景；视频卡片应显示自动截取的画面；剧本和音频应显示各自的视觉封面，而不是纯文字列表。
3. 打开图片详情，应看到适合屏幕大小的大图；打开视频详情，应看到带封面的播放器并能播放、拖动进度。

## 十五、验收旧站数据迁移工具

```powershell
$env:DB_HOST = "旧数据库地址"

```

`data:verify` 会把 `import.sql` 导入一次性内存数据库，不会修改本地网站数据库。它会逐表核对 `expected-counts.json` 并执行外键检查；看到“数据量与外键均正确”才进入下一步。

转换结果位于 `migration-work/converted/`：

- `import.sql`：D1 导入文件。
- `verify.sql` 和 `expected-counts.json`：表数量与外键核对。
- `r2-files.json`：旧头像、资料和首页背景的文件迁移清单。
- `warnings.json`：需要人工确认的旧数据问题。

验证通过后还要人工完成两件事：打开 `warnings.json`，确认它是空数组或逐条处理；再检查 `r2-files.json` 的每项 `sources`，保证至少一个旧文件路径真实存在。云端部署恢复后，才把 `import.sql` 导入测试 D1，并用 `data:upload` 上传文件。

`migration-work/` 已被 Git 忽略，不会上传真实数据。先在独立测试 D1/R2 中验收，不能直接覆盖未来正式库。
