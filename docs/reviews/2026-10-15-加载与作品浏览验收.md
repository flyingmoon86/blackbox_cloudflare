## 实现与延迟定位（Source）

- `public/navigation-preload.js`：原先先发现五个入口、再统一下载资源；其中一个入口慢，会推迟已经发现的资源。现在发现页面和下载资源共用最多两个并行任务的队列，当前页优先，资源发现后立即入队。共享 URL 去重，最多 40 个资源任务，保留单任务及整体超时。
- `public/curtain-boot.js`：资源清单尚在增长时显示“正在获取页面与资源清单”和已就绪数；清单确定后才展示确定进度。仍为“正在加载黑匣子”，没有首屏跳过入口。完成、部分失败、超时分别处理，没有为了进度好看而伪报完成。
- 八张内置手机舞台背景采用独立 WebP 编码，保持原有像素尺寸和透明层。`picture` 在 900px 及以下选择手机版；预加载解析同一媒体条件，避免两套背景同时下载。自定义图对、管理员编辑预览保持原 URL 和动态替换行为。
- 新增 `public/work-browse.js/css`：作品卡进入视口时最多自动准备四张低清封面；悬停/键盘聚焦可优先准备，每页总尝试最多八张，同时最多两张。离线、节流量和 2G 停止准备；页面隐藏、导航开始时停止队列，取消导航后可恢复。没有预取作品详情 HTML。
- 新的 `previewOnly=1` 请求只返回公开作品、已审核且属于该作品的低清封面。每次先鉴权，再处理 HEAD/Range/304；低清不存在就返回 404，不回退原图。原有列表封面接口仍保留旧资料的回退能力。
- 详情保留浏览器原生的大图请求。大图未完成时可先显示低清，随后替换；横竖版各自预留封面高度，完整图片使用 `object-fit: contain`。预览样式在管理员预览和无脚本场景也会加载。低清失败继续等原生大图；大图失败且低清成功时保留低清。
- 返回链接保留列表的查询参数、滚动位置和作品焦点；浏览器后退仍由浏览器恢复滚动。实测发现仅在 `pageshow` 恢复焦点会等慢背景图，已提前到 DOM 就绪，并避免晚到的图片重复抢焦点。用户已开始操作时不覆盖其焦点。
- 已复查旧 loading/transition：`navigation-light.js` 没有导航前的预取等待，`experience.js` 没有旧首屏 3.6 秒 loading。幕布源页面点击处理不拦截原生导航、不等待预取；目标页揭幕不等封面或整页 `load`。其他菜单、首页切幕和媒体交互仍有各自的计时，不属于跨页面导航等待。
- 本轮没有调整第 3 项幕布节奏。`curtain.css` 与本轮开始前快照 SHA-256 相同：`073dc8fccb4e7a8e204ba80259c5d59eba8bd72e2732897442702afe3ca6e860`；合幕 150ms、揭幕 600ms 保持原值。

## 前后对照

前：`.wrangler/evidence/2026-10-15/loading/before-verified/`。
后：`.wrangler/evidence/2026-10-15/loading/after-final/`。

- 八张舞台背景文件：6,826,110 → 4,047,518 bytes，手机减少 2,778,592 bytes（40.71%）。保持像素尺寸，减重来自编码；不是把图片裁小。
- 桌面首次资源准备完成：834 → 698ms；幕布完全移除：1,442 → 1,306ms。首次观察窗口接收响应体 9,468,252 → 9,486,196 bytes；增加来自新增功能资源，桌面没有背景减重收益。
- 手机首次资源准备完成：900 → 437ms；幕布完全移除：1,529 → 1,044ms。接收响应体 9,468,252 → 6,707,601 bytes，约减少 29.16%。请求数 73 → 75；减少的是传输体积，不是请求总数。
- 弱网 CPU 限速：两版都触发首次准备超时，分别约 10,693 / 10,697ms 结束准备，11,387 / 11,336ms 移除幕布。新版首页背景在揭幕时已就绪，但所有导航资源没有全部完成缓存。不能据此声称弱网首开更快或以后所有导航都无需网络。
- 点击到幕布计算 transform 首次变化，桌面 27.1 → 10.9ms；手机 22.1 → 10.8ms；弱网限速 96.5 → 73.9ms。此指标在 `requestAnimationFrame` 采样，不是物理屏幕或手指到显示的延迟。
- 同一点击到原生 Document 请求发出，新版分别 8.6 / 9.1 / 25.4ms。完整封面就绪分别 1,255 / 1,254 / 1,942ms，其中包含人为注入的 1,200ms HTML 响应延迟。网络等待没有变成幕布启动门槛。
- 本次样本三种配置都没有横向溢出，详情 CLS 均为 0。首页原始 CLS 分别 0.0600 / 0 / 0.4805，非零位移发生在首次 loading 全遮挡期间；剔除该遮挡阶段的可见位移诊断为 0。后者是诊断指标，不能替代原始 Web Vital。
- 三种配置从第六部作品返回列表，滚动差均为 0px、焦点均回到 `/productions/6`。慢网焦点修复后也不再等待整页图片完成。

字节口径：以上“接收响应体”来自 CDP `Network.dataReceived.encodedDataLength`，统计观察窗口内收到的字节，包括已收到的部分响应，不含 HTTP 头。服务端准备的 body 字节、Resource Timing 的完成子资源 transferSize、CDP 完成响应含头字节另行记录，不能混用。慢网触发中断，不能拿服务端准备的响应大小当实际下载量。

## 限制与取舍

- 原列表封面 URL 保留兼容回退；严格预热 URL 独立，因此可能多一次低清请求。预热有 4/8/2 上限；没有宣称请求零增加。封面继续 `private, no-cache`，缓存复用可能需要鉴权后 304，不能绕过当前权限。
- 省流量/2G 不主动预热、离线与超时让页面正常可用。弱网下首页全部统一加载仍受体积、字体和带宽限制；10 秒预算不会保证全部资源成功。
- 未验证：实体手机、iOS Safari/Firefox、真实移动网络、生产 CDN/D1/R2 延迟、真实作品图片的画质差异和线上流量/费用。没有全站所有详情预加载，也没有增加 Service Worker 或 SPA 导航。
- 原始 JSON、截图和日志存于本地 Git 忽略目录 `.wrangler`；脚本可重跑。历史基线快照只在本机存在，迁移工作区时需单独保留它。本文的结果仅代表这次本地验收。

## 重跑

先运行 `npm run assets:build`。Node.js 24+、本机 Edge 与 Playwright 可用时执行：

```powershell
node scripts/check-loading-performance.mjs --label=after
node scripts/check-loading-performance.mjs --mode=interactions --label=work-browse
# 仅在本轮开始前的快照仍存在时执行；不要用当前源码重建“优化前”快照。
node scripts/check-loading-performance.mjs --label=before --snapshot=.wrangler/loading-baseline
```

脚本默认使用本机 Codex bundled Playwright，可用 `--playwright=<绝对路径/index.mjs>` 指定其他安装；`--profile=desktop|mobile|mobile-throttled` 可缩小性能检查范围。

幕布回归使用 `PLAYWRIGHT_MODULE`（模块路径/文件 URL）、`BROWSER_CHANNEL=msedge` 和 `EVIDENCE_DIR`。本轮把 `EVIDENCE_DIR` 明确设为 cloudflare 内的 `.wrangler/evidence/2026-10-15/curtain-final`，避免旧脚本默认写入大作业。执行 `node scripts/check-work-curtain-browser.mjs`。
