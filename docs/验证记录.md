## 记录原则

- 区分**源码判断**（看代码得出）、**自动化结果**（测试/脚本通过）、**浏览器实测**（实际打开页面）、**线上事实**（登录生产核验）。
- 没有检查过的写「未验证」，不用代码推断补齐。
- 每次发布或验收后把结果追加到下面的表格。

## 未验证 / 待办事项

按优先级排列：

1. **R2 文件备份**——现有备份命令只导出 D1，完整恢复流程未补齐。接手后应尽快建立并演练。
2. **恢复演练**——从未实际演练过一次从备份恢复完整网站。
3. **线上人工验收**——权限、上传、审核、后台导入、恢复操作需再做一次实际验收（清单见[本地验收指南](本地验收指南.md)第三节）。
4. **R2 直传是否启用**——需登录 Cloudflare 检查环境密钥。
5. **自动审核规则的业务依据**——没有完整记录每条规则当时的业务考虑。修改前应与负责内容审核的人确认需求。
6. **为什么选这套 Cloudflare 组合**——没有可靠资料说明最初选型原因。

## 日志能回答什么

系统记录：请求编号、路由、状态、总耗时（Server-Timing）。

系统**不**记录：逐条数据库查询耗时。

因此「哪个查询最慢」不能从现有日志直接得出；性能问题要另做测量。
