# 演职人员批量导入 v2（V3.5 已发布，兼容 v1）

## 已确认范围

一次只导入一个现有作品的一个演出版本，处理作品与队员的演职关联，不处理照片、附件、账号、手机号、邮箱、证件或其他人事信息。仅管理员可以下载模板、预览、确认、查看报告和撤销。

- XLSX 两张表：`演职人员导入`、`填写说明`；CSV 使用 UTF-8。
- 新模板固定三列：`*姓名`、`*类别`、`*角色或分工`，不填写系统编号。第 2 行是示例，只有完全未改动的示例行会跳过；改写该行的真实内容不会被吞掉。
- 不超过 50 条数据、5MB；类别为“演员”或“后台与创作”。一人多角和 AB 角分别填写多行。
- 按去首尾空格的姓名匹配。ASCII 大小写与 SQLite NOCASE 保持一致。唯一同名自动关联；多个同名必须显式选择，可先打开候选档案核对。
- 未找到档案时，由管理员选择关联已有档案、新建最小档案或排除此行。新建只需姓名；后台自动生成 `BB-UUID`，填写者和新模板预览无需提供编号。
- 只新增演职关联，已存在的完全相同关联跳过，不删除或覆盖原名单。已有队员简介、年级、入队年份、头像、编号和账号绑定保持原样。
- 兼容此前下载的四列 v1 XLSX/CSV：旧编号仍参与安全匹配与冲突检查，不能静默丢弃；原有空编号补充规则保留。解析后使用文件实际模板版本作为幂等键，重复上传旧文件仍回到旧批次。本轮无数据库迁移。
- 本版不提供任意字段映射、不创建新作品、不提供面向第三方的公开导入 API。

## 使用入口

管理员工作台 → “填资料” → “表格导入演职人员” → 选择已有作品 → 下载模板 → 选择版本并上传 → 核对每行 → 保存选择并重新检查 → 勾选确认入库。原作品详情的导入入口继续保留。

错误行会阻止整批提交；可以修正表格重新上传，也可以明确排除该行后提交其余已确认内容。系统不会擅自部分成功。网络结果不确定时先刷新批次页，同一批次重复确认不会重复入库。

本地待发布改进：确认入库后显示不确定进度条，并读取当前批次状态；D1 整批事务没有可靠逐行完成比例，因此仅在数据库确认 `committed` 后显示完成并跳到结果。若网络响应丢失，页面提供批次核对入口，不自动重复写入。无 JavaScript 时仍用原生表单。状态读取仅对已登录管理员开放。确认请求不再读取全部明细行，日志记录匿名化的耗时和批次行数以便排查。

工作台“待处理 → 账号与处理记录 → 查看导入记录”可查看结果、下载错误/跳过行 CSV、查看操作记录及安全撤销。报告保留原表行号帮助定位错误，但不再输出人员编号列。新建档案有后续修改或引用时保留，不会强行删除。完成和撤销记录进入管理员站内提醒，提醒不计入待办任务。

## 实现与数据设计

- `src/services/credit-import/schema.ts`：模板版本、字段、枚举、长度和文件限制的配置。
- `parser.ts`：CSV 状态机、UTF-8 验证、XLSX 安全解析。限制 ZIP 文件数、单文件/总解压大小、工作表坐标与单元格数量，拒绝加密、ZIP64、宏、外部链接、合并单元格及公式。
- `store.ts`：人员匹配、冲突识别、显式选择、重复关系检查与批次预览。
- `commit.ts`：D1 原子入库、受保护撤销、180 天明细清理。
- `src/routes/credit-import.ts`、`src/views/credit-import.ts`：管理员鉴权、限流、CSRF、SSR 原生表单。无 JavaScript 可完整操作。
- `templates/production-credit-import-v2.xlsx`：新版三列双表模板；构建时打包到 Worker，仅通过管理员下载端点提供。CSV 从字段配置生成。v1 文件仅保留作兼容回归，不再用于下载。
- `migrations/0019_credit_imports.sql`：增量迁移，不重建原表，不改原 ID 或媒体键。

新增 `member.external_id`（可空、唯一 NOCASE 索引）与 `import_revision`；成员资料更新触发递增版本号。`production_credit` 增加导入批次及后续修改标记，旧数据默认不属于任何批次。

批次表记录作品/版本快照、操作者、文件 SHA-256、模板版本、状态、计数与乐观锁 revision；明细表保存标准化输入、原校验错误、人员选择与新增关系 ID；档案变更表只记录新建或外部ID补充的撤销依据；事件表保留操作摘要。原始上传文件不存入 R2 或数据库。

确认时在同一 D1 `batch` 内使用 CHECK 守卫校验批次版本、父子归属、成员版本、同名/编号冲突和关系状态，再一次性写入档案、关联和审计。任意失败全部回滚，不会留下部分名单。并发或过期预览返回 409，刷新后重新检查。

幂等键为作品 + 版本 + 文件 SHA-256 + 模板版本，活动/已提交批次受唯一索引保护。撤销后可以重新导入；旧批次不会再次提交。文件指纹保留用于防重，180 天后清理行明细、档案变更快照和原文件名，保留简要审计，停止提供撤销。定时任务每次最多清理 20 个批次。

撤销只删除本批未修改的新增演职关联；新建档案必须版本未变且不存在账号、认证申请、资料、演职关系、献花、加入申请、贡献者或其他导入批次引用。外部ID补充仅在快照版本仍一致时还原。有冲突的记录保留并标注，不强行恢复整个旧数据库。

## 端点

以下端点全部要求当前有效管理员身份；所有 POST 还要求同源及有效 CSRF。

- `GET /admin/credit-imports/new`：直接选择已有作品；有效 `production_id` 跳到原上传页，无效参数 400、不存在作品 404。
- `GET /admin/productions/:id/credits/import`：上传页。
- `GET /admin/productions/:id/credits/import/template.xlsx` 或 `.csv`：模板。
- `POST /admin/productions/:id/credits/import/preview`：最多 5MB 表格，生成预览；每管理员每小时最多 30 次。
- `GET /admin/credit-imports?page=1`：历史，每页 20 条。
- `GET /admin/credit-imports/:batchId?q=姓名`：预览/结果及可关联档案搜索，最多 100 个备选。
- `POST /admin/credit-imports/:batchId/resolve`：保存选择、重新检查。
- `POST /admin/credit-imports/:batchId/confirm`：确认入库。
- `POST /admin/credit-imports/:batchId/rollback`：安全撤销。
- `GET /admin/credit-imports/:batchId/errors.csv`：错误及跳过行报告，单元格做公式注入转义。

动态页面与下载均为 `private, no-store`。人员信息不会通过新接口向普通用户公开；导入后正常演职关系和新建公开队员档案按现有网站规则展示。不要在自由文本中填写敏感信息。
