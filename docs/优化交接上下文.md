## 设计方向（2026-09-18 冻结）

默认以已部署版本为视觉基准。用户明确表示不满意时，优先回退到部署版本，不在其上继续叠加修补。

已冻结的六个方向：演出时间轴、剧照沉浸浏览模式、作品幕后卡片、舞台灯光式页面转场、图片悬停“聚焦”、页面内容删减（重复入口、多余分隔线、过多英文副标题、首页重复作品介绍、无实际功能按钮、重复资料、空卡片与空标题）。

第 7 项：更炫酷的舞台动效，在部署版本基线上增强，不重做信息架构。

第 8 项（执行纪律）：先冻结方向并写入本文件与 `.agents/skills/blackbox-optimize/SKILL.md`，再逐项实施；每完成一项补测试、PC/手机截图与键盘、触屏、减少动画验收；代码、文档分开中文提交；未经用户明确要求不部署、不推送、不重置 D1。

## 当前任务（已完成本地收口）

用户要求继续优化黑匣子话剧队网站，当前优先处理两件事：

1. 真实诊断管理员通知请求，避免前端静默失败掩盖后台提醒故障。
2. 修复剧照详情页体验：打开剧照后可返回原作品剧照集，避免大图遮挡；增加上一张/下一张、方向键浏览、精确恢复原分页和媒体失败退路。

## 未来优化可能性

以下是后续候选方向，按“收益高、风险可控、符合现有架构”排序。它们只是路线记录，不代表已经授权实施。

### A. 可直接排期

1. **统一加载、空状态和错误状态**
   - 范围：作品列表、资料库、队员名录、通知面板、上传流程。
   - 收益：减少“页面没反应”和“没有数据但不知道为什么”的困惑。
   - 做法：统一使用可读的状态文案、重试按钮、返回路径和 `aria-live`；不引入前端框架。
   - 验收：正常、空数据、失败、超时四种状态各有截图或请求证据。

2. **全站键盘与触屏可用性回归**
   - 范围：导航菜单、对话框、筛选器、分页、剧照浏览、上传取消。
   - 收益：提高可访问性，也降低移动端误触和焦点丢失。
   - 验收：Tab 顺序、Escape 关闭、Enter/Space 激活、方向键不误拦截；主要点击热区至少 44px。

3. **图片和媒体性能治理**
   - 范围：封面、剧照缩略图、海报、预览媒体。
   - 做法：延迟加载非首屏资源、保留明确尺寸比例、失败时显示替代内容；评估缩略图尺寸和缓存头，不修改原文件。
   - 验收：移动网络下首屏请求数、图片体积、LCP/CLS 和失败请求有前后数据。

4. **作品档案信息架构继续收敛**
   - 范围：版本、主创、资料、剧照四个区域。
   - 做法：保持版本上下文可见；增加“资料类型筛选”和“回到当前版本”路径；避免把同一资料重复展示成多个入口。
   - 风险：容易影响现有链接和分页，必须先补路由/查询参数测试。

5. **后台通知的可观测性**
   - 范围：通知请求、dismiss、会话过期、后台接口异常。
   - 做法：继续使用不含用户隐私的结构化 console 信息；为请求结果补状态分类和耗时，禁止记录 cookie、CSRF、正文和用户资料。
   - 验收：401、403、404、5xx、超时、无效 JSON 均能区分，且页面有可操作恢复方案。

### B. 需要产品决策

1. **剧照浏览是否改为同页灯箱**
   - 方案一：保持当前详情页，利于分享、刷新和无 JavaScript 访问。
   - 方案二：增加轻量灯箱，浏览更快，但需要处理焦点、滚动锁定、移动端手势和历史记录。
   - 建议：先完成当前详情页导航和失败退路，再依据真实使用反馈决定。

2. **作品档案是否允许用户按演出年份、版本或资料类型过滤**
   - 过滤会提升查找效率，但会增加 URL 状态、分页边界和空状态组合。
   - 如果实施，应使用 GET 查询参数并保留可复制链接，不使用只存在于前端内存的筛选状态。

3. **是否增加公开的演出日历/时间线**
   - 价值：让访客更快理解剧团活动脉络。
   - 前提：确认现有数据中的年份、版本和演出日期足够可靠；否则应先设计“日期未知”的表达，不能凭空补全。

4. **是否开放更完整的资料说明和贡献者归属**
   - 价值：提高档案研究和队内协作价值。
   - 风险：涉及隐私、署名、撤回和审核权限，必须先确定公开字段和管理员操作规则。

5. **是否做轻量的内容搜索增强**
   - 方向：标题、作品、版本、文件名的分组结果和关键词高亮。
   - 前提：先确认数据规模；小规模可继续 SQLite 查询，大规模再评估 FTS，避免过早引入复杂索引。

### C. 暂不建议

- 为公开页面引入 React/Vue 等前端框架：当前 SSR + 原生脚本已能覆盖需求，会增加构建和状态同步成本。
- 引入 ORM 或替换 D1 数据层：与当前单 Worker、迁移和测试约定不匹配。
- 先做复杂手势、自动轮播和视差动画：会增加可访问性、减少动画和移动端性能风险。
- 仅通过隐藏按钮或前端路由保护管理员功能：服务端鉴权必须始终是唯一权限边界。
- 在没有数据需求前接入分析平台、付费图片 CDN 或外部搜索服务：扩大隐私、成本和部署风险。
- 为了“看起来更现代”大规模重做色彩和排版：优先修复信息层级、遮挡、失败恢复和可操作性。

### 推荐推进顺序

内容删减审查 → 演出时间轴 → 剧照沉浸浏览模式 → 作品幕后卡片 → 舞台灯光式页面转场 → 图片悬停“聚焦” → 更炫酷的舞台动效。默认以部署版本为视觉基准，用户不满意时先回退再重做。
