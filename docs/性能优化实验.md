# 真实页面查询优化实验

执行日期：2026-10-05（北京时间）。本轮代码在 Cloudflare 项目与独立大作业项目同步实现，final 队用迁移版保持原状。2026-10-05 已应用生产迁移并发布；未宣称线上整页已经提速。

## 业务问题与改动

作品详情按作品、演出版本、批准状态筛选资料，再按创建时间和 ID 倒序分页。原有索引分别偏向版本或作品，不能在全部等值条件下同时提供所需顺序。新增索引只覆盖这条真实路径，保留其他索引以支持不同排序；查询文本由真实路由和实验脚本共同引用，避免演示 SQL 与实现脱节。

```sql
-- Match the detail page equality filters before its stable chronological order.
-- Keep existing indexes: other queries order by id or span multiple editions.
CREATE INDEX ix_resource_production_edition_order
ON resource(production_id,edition_id,status,created_at DESC,id DESC);
```

公开作品列表使用已生成预览图并延迟加载，作品详情保持原图；预览缺失时回退原图，隐藏和待审内容仍被权限检查拦截。GET、HEAD、条件请求都有回归验证。没有新增页面缓存或改变上传方式。

## 实验方法

环境：Windows，Node v24.19.0，SQLite 3.53.3。使用完整课程迁移生成 30 部作品、150 个版本、30,000 条合成资料，含待审状态和相同时间记录。两个独立内存库具有相同数据；仅优化库增加索引。两边均 ANALYZE、预热 20 次，交替先后顺序采集 80 个样本，每样本执行 10 次已准备查询并除以 10。样本是查询均值，因此 p95 是批次均值的 p95，不是单次请求 p95。

100 组分页、空页和作品/版本错配查询均逐项一致；两个库均无外键错误。原始 80 个耗时样本、执行计划、SQL、参数及结果哈希见 query-performance-20261005.json。

## 查询结果

### 作品版本资料第一页

中位数：0.05331 → 0.02678 ms，约 1.99 倍。批次均值 p95：0.06292 → 0.03427 ms。

优化前：SEARCH resource USING INDEX ix_resource_edition (edition_id=? AND status=?)；USE TEMP B-TREE FOR ORDER BY。
优化后：SEARCH resource USING INDEX ix_resource_production_edition_order (production_id=? AND edition_id=? AND status=?)。

### 作品版本资料第五页

中位数：0.08118 → 0.02874 ms，约 2.82 倍。批次均值 p95：0.09443 → 0.03176 ms。

优化前：SEARCH resource USING INDEX ix_resource_edition (edition_id=? AND status=?)；USE TEMP B-TREE FOR ORDER BY。
优化后：SEARCH resource USING INDEX ix_resource_production_edition_order (production_id=? AND edition_id=? AND status=?)。

### 作品版本资料总数

中位数：0.02158 → 0.00363 ms，约 5.94 倍。批次均值 p95：0.02268 → 0.00370 ms。

优化前：SEARCH resource USING INDEX ix_resource_edition (edition_id=? AND status=?)。
优化后：SEARCH resource USING COVERING INDEX ix_resource_production_edition_order (production_id=? AND edition_id=? AND status=?)。

## 代价与适用边界

新增索引占用约 1.25 MiB 分配页空间（1,306,624 字节）。固定 200 条新增资料的事务含回滚，预热 2 轮后交替测量 20 轮，中位数由 1.7109 增至 1.9104 ms（约增加 11.7%）。这不是磁盘持久化提交耗时，不能据此推断生产写入吞吐。

缩小数据集、改变状态和版本分布、缺少统计信息都可能使优化器选择不同计划。生产备份上的原计划使用 ix_resource_public_order 并无临时排序，主要差异是版本过滤；不能把合成样本的 TEMP B-TREE 描述成线上已有事实。

## HTTP 对照与图片流量

另外对 6,000 条合成资料的本机回环 HTTP 服务测量首页、作品详情和资料列表；按优化前/后/后/前四个测量段，每段每路径预热 5 次，每条件采集 50 个完整响应。只切换同一索引，页面代码与数据一致，300 个计时响应全部 HTTP 200。
- /：中位数 15.625 → 15.272 ms。
- /productions/1：中位数 15.573 → 15.588 ms。
- /resources：中位数 15.595 → 14.946 ms。

本轮 HTTP 中位数基本在 15 ms 左右，作品详情未观察到整页加速；SQL 微秒级节省不等于用户等待时间同比缩短。没有把这组结果包装成整站变快。

使用 2026-10-04 发布前本地生产备份只读统计：11 个公开作品封面均有预览图；原图合计 5,443,366 字节，预览合计 357,936 字节，候选传输量减少约 93.4%。这是备份文件大小对比，不是实际访问耗时；课程包不复制真实原件或数据库行。实际节省取决于页面展示、懒加载、缓存命中和缺图回退。
