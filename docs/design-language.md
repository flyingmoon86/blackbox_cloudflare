# 黑匣子幕后档案：设计与验证

## 参考观察

实际浏览 https://ak.hypergryph.com/#world ，在桌面 1280×720 和手机 390×844 观察页面。桌面主题索引位于左侧，进入「源石」后以单一标题、短说明与抽象粒子图形形成焦点；箭头成功切到「源石技艺」。参考的主题内容切换仍共用 `#world`，并非各自具有独立 URL。手机改为上图下文和折叠菜单，保留边缘章节标记。手机箭头的内容切换未得到确认，不作为本站实现的验证依据。

提炼原则：一次聚焦一个主题；索引位置稳定；大标题与短导语先建立层级；细线网格、抽象图形和留白建立空间感；少量强调色标示当前位置；动效服务于切换而不抢占阅读。没有复制素材、文案、品牌或代码。

## 本项目方案

沿用工作台、队员认证、账号管理及现有业务操作独立页面。系统信息细分为系统架构、业务流程、数据库结构、文件存储四页，具体地址和业务盘点见 `admin-page-organization.md`。

系统信息统一为「黑匣子 · 幕后档案」：墨黑与暗绿内页、暖白内容纸面、琥珀当前位置、衬线标题、原创舞台平面线稿与章节编号。标题保持直白业务名称，导语适度采用档案和舞台语气，数据、操作和错误提示仍使用准确说明。

桌面左侧主题索引与底部相邻主题导航互相补充；窄屏转为四列，手机转为两行，所有主题均可直接进入。使用原生链接和服务器路由，保留刷新、前进后退；数据库保留 `?table=`，流程保留 `?flow=`。不劫持滚轮或键盘方向键，不增加路由框架。

地图保留 2.5D 交互、键盘模块按钮和详情；数据库保留真实外键关系图、搜索与单表字段；存储保留来源、时间、连接结果和不可获取指标。仅短暂内容入场动画，遵循 `prefers-reduced-motion`，无连续装饰动画。原有权限、表单、接口和业务服务未因视觉调整改变。

## 本轮修改位置

- `src/views/system-chapters.ts`：章节元数据、原创 SVG、主题导航和相邻页链接。
- `src/views/system-info.ts`：章节框架、流程展示与状态区域。
- `public/system-info.css`：主题布局、地图与表结构容器、移动适配、焦点与减少动效规则。
- `src/views/admin.ts`、`public/workbench.css`：工作台、认证、账号页面统一标题和侧栏视觉，保留原业务控件。

## 验证结果

- 后端回归 108/108 通过，包含各主题页面及数据接口对匿名、普通用户、队员、禁用管理员的拒绝访问，及原审核、账号、导入、上传行为。
- TypeScript、格式检查、Cloudflare dry-run 构建通过。未部署生产。
- 本地合成数据：四主题到达；架构 D1 按钮 Enter 选择；数据库选 production 后刷新恢复；数据库至存储的后退与前进恢复地址；手机流程切换至资料读取；手机后台菜单 Enter 展开并进入账号管理；账号筛选及无匹配状态正常。
- 实际检查 1440×1000 桌面与 390×844 手机。手机存储页面无横向溢出，账号操作采用纵向卡片；浏览器未记录脚本错误。
- 前轮已经实际验证认证通过及账号禁用/恢复，本轮保持接口不变并通过回归覆盖。解绑、删除由隔离测试覆盖，未操作真实用户。

预览使用本地临时 D1/R2 和合成账号。实时结果仅代表该预览环境，不代表生产状态。R2 平台对象总数、实际用量及剩余配额仍不可获取，不用应用台账冒充平台统计。
