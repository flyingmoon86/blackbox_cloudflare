# 话剧队网站 · 项目上下文

更新日期：2026-09-08。

本文用于接续开发，汇总项目目标、当前实现和后续方向，替代早期的《计划.txt》《小计划.md》。当前行为以代码为准；《学习文档.md》记录开发过程，其中旧阶段的设计不一定仍然适用。

## 1. 项目目标与开发背景

建设私人话剧队网站，保存历届队员档案和团队作品。核心模块是名人堂、资源库、账号与队员认证、管理员管理和首页公告。

项目同时用于学习网站开发：开发者有 Python、SQL 和 Git 基础，使用 Windows。保持实现易懂、中文说明清晰，逐步完善已有功能。当前是本地 Flask 学习项目，仓库没有完整的生产部署配置。

## 2. 技术与目录

- 后端：Python、Flask；通过 Jinja2 渲染页面。
- 数据库：MySQL，使用 Flask-SQLAlchemy 和 PyMySQL，连接字符集为 utf8mb4。
- 前端：Bootstrap 5.3.3（通过 CDN 加载）、HTML 和少量原生交互，无独立前端构建流程。
- 登录：Flask session；密码通过 Werkzeug 生成和校验哈希。
- 配置：python-dotenv 读取本地 `.env`。

主要文件：

- `app.py`：应用初始化、权限装饰器、所有业务路由及上传处理。
- `models.py`：账号、队员、申请、邮件令牌、公告、献花、资料、作品、演职员、剧团设置及队员—资料关联表。
- `theater.py`：作品管理、演职员关联、资料归类与审核、公开剧团设置。
- `migrate_theater.py`：特色升级，新增作品表、演职员表、剧团设置与资料审核字段，补充首次入队提示状态。
- `account.py`：邮箱验证、邮件发送、密码找回和一次性令牌处理。
- `migrate_priority3.py`：补充邮箱与登录版本字段、邮件令牌表和作品关联表，可重复执行。
- `docs/邮箱配置指南.md`、`docs/网站使用指南.md`：管理员邮箱配置与用户操作说明。
- `config.py`：数据库、密钥、上传目录、文件类型和大小限制。
- `seed.py`：创建缺失的表，按姓名去重插入演示队员；不创建管理员。
- `migrate_join_results.py`：为已有数据库补充申请结果确认字段，可重复运行。
- `migrate_flowers.py`：为已有数据库创建献花表，可重复运行。
- `static/members.css`、`templates/_flower.html`：队员名片样式和共用献花表单。
- `tests/test_flowers.py`：献花限额、跨日、权限、删除清理和迁移回归测试。
- `tests/test_join_results.py`：使用内存数据库验证申请审核通知和重新申请流程。
- `templates/`：首页、名人堂、账号、个人中心、用户管理、公告和资源页面。
- `static/uploads/`：队员照片；`static/resources/`：正式资源文件。
- `static/pending/`：历史预留目录，目前通过数据库状态区分待审资料；此目录和 `static/resources/` 的静态 URL 均已关闭。
- `docs/学习文档.md`：分阶段实现说明和学习记录。
- `docs/补充计划.txt`：用户提出的体验问题及优先级，需结合本文判断完成情况。

## 3. 当前功能与权限

“游客”指未登录者；“访客”是已登录的普通账号，对应数据库角色 `user`。

- 游客：浏览首页及最新五条公告，注册、登录。名人堂列表、详情和资源库均要求登录。
- 访客（`user`）：浏览、搜索和下载；修改密码；申请认证为队员。
- 认证队员（`member`）：增加修改本人绑定档案、上传资源的权限。本人可修改简介、届别、代表作和照片，直接生效。
- 管理员（`admin`）：管理队员档案、禁用或删除用户、审核入队申请、撤销队员认证、发布或删除公告、上传或删除资源。

注册采用用户名和密码，可填写邮箱，默认账号状态为 `active`；入队认证需要审核，不是账号注册审核。注册后在个人中心申请队员认证。邮箱先保存为待验证，验证成功后才能用于密码找回；不支持手机验证。真实发信需要配置 SMTP，目前尚未配置和验收，页面会明确提示。

名人堂支持姓名/简介关键字搜索、入队年份筛选、每页十条分页及档案详情。档案含姓名、简介、入队年份、届别、代表作和照片；队内职务字段已删除。保留代表作文本，并支持多选关联现有资源。队员可编辑本人关联，管理员可编辑所有档案关联；资源详情与队员档案支持双向跳转。

首页采用舞台与票根风格，显示最新五条公告；公开公告列表支持每页十条归档，详情页显示完整正文。新增关于我们、联系我们页面，公开联系邮箱为 `moonflying56@gmail.com`。手机端导航支持折叠。

邮箱验证和重置链接有效期为 30 分钟，只保存令牌摘要，使用后失效；GET 打开验证链接不会直接修改邮箱，需点击确认。每个账号每分钟最多发一封、24 小时内最多十封。修改或重置密码会增加登录版本，使旧会话和旧邮件链接失效；找回请求使用统一响应，页面不直接披露邮箱注册状态。邮箱绑定需要当前密码，登录、注册和邮箱操作带会话令牌校验。

队员列表采用响应式照片名片，桌面三列、平板两列、手机单列；无照片时显示姓名首字，简介截断、完整内容在详情页查看。列表和详情均可献花并显示累计数量。所有正常登录账号（访客、队员、管理员）每天可向每位队员献花一次，按北京时间自然日计算；换浏览器或重新登录不会重置，数据库唯一约束防止重复计数。献花采用 POST 和会话令牌校验，列表献花后保留筛选和分页。删除账号或档案时清理对应献花记录，累计数量随之减少。

资源库已拆为“经典剧目”和“其他资料”。作品包含简介、年份、演员与角色、后台成员与分工，以及剧本、台本、剧照、视频、音频等文件。未归类资料保持独立。管理员创建和编辑作品、维护演职员及归类；队员上传时可选所属作品，但必须经管理员审核通过才入库。管理员上传直接通过。管理员入口显示待审数量；队员在“我的上传”查看待审核、已入库或驳回理由，可按理由重新上传。允许的扩展名见 `config.py`，请求上传体积上限为 200 MB。

待审/驳回文件只有上传者和管理员可查看、预览或下载；其他登录者只能看已通过的资料。所有文件通过业务接口鉴权，静态文件地址返回 404。删除作品只删除档案与演职员，文件回到未归类；删除队员清理演职员关联并将指向该档案的待审入队申请驳回、保留理由。

管理员可通过“剧团设置”维护真实剧团名称、成立年份、QQ群、公众号、招新要求和近期时间地点，以及上传、替换、移除公开背景剧照。首页会自动虚化背景并叠加暗色遮罩；未上传时用舞台底色。当前真实名称等信息尚未提供，保留通用名称，空字段不显示。联系邮箱继续使用 `moonflying56@gmail.com`。

## 4. 入队认证与数据模型

个人中心有两种入队申请：

1. `bind`：选择尚未绑定、也未被待审核申请占用的队员档案。
2. `new`：名单中找不到自己时填写资料，申请新建档案。

申请使用 `JoinRequest` 保存，状态为 `pending`、`approved` 或 `rejected`。通过 `bind` 申请后绑定现有档案；通过 `new` 申请时先创建档案再绑定。用户角色随之变为 `member`。管理员可驳回并填写理由，或撤销认证并释放绑定。

审核通过或驳回后，申请者的个人中心入口显示红色数量提醒，个人中心展示审核结果。仅进入页面不会消除提醒，必须点击“我知道了”；确认状态写入 `result_acknowledged`，跨登录保留。确认后申请者不再看到该结果或历史记录，管理员仍保留审核记录。

驳回理由为必填。申请者可修改预填的上次资料重新申请，也可以切换绑定/新建方式；确认提醒后仍保留重填草稿。重新提交不会自动确认旧通知。已处理的申请不能再次审核。每次请求刷新账号身份，审核通过后刷新页面即可看到队员徽章和上传入口。

数据库模型：

- `Member` / `member`：名人堂档案。
- `User` / `user`：用户名、密码哈希、角色、账号状态和 `member_id`。`member_id` 有唯一约束，一个档案最多绑定一个账号。
- `JoinRequest` / `join_request`：申请人、申请类型、目标档案或新档案资料、审核状态、备注和时间。
- `Announcement` / `announcement`：公告标题、正文、时间。
- `Resource` / `resource`：资源标题、类型、说明、磁盘文件名、下载显示名、下载次数和时间。
- `Flower` / `flower`：献花账号、目标队员、北京时间日期；三者构成唯一约束。
- `EmailToken` / `email_token`：验证/重置令牌摘要、目标邮箱、用途、有效期、消费状态和登录版本。
- `member_resource`：队员和现有资源之间的多对多关联。删除任一端时解除关联。

不要根据旧学习章节恢复已删除的通用更新申请、资源上传审核或旧身份字段。数据库角色的实际取值是 `user/member/admin`。

## 5. 本地运行

在项目根目录使用 PowerShell。准备 Python 环境和可访问的 MySQL 数据库，数据库使用 utf8mb4。当前仓库没有依赖清单，代码直接依赖可按以下方式安装：

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install flask flask-sqlalchemy pymysql python-dotenv
```

已有 `venv` 时可跳过创建。根据本机 MySQL 认证方式，可能还需要 PyMySQL 的额外认证依赖。

根目录 `.env` 需提供以下变量，值使用本机实际配置，不要将密码写入文档或提交 Git：

```dotenv
DB_USER=your_database_user
DB_PASSWORD=your_database_password
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=theater
SECRET_KEY=replace_with_a_random_secret
```

数据库本身需预先创建。新开发库可运行：

```powershell
.\venv\Scripts\python.exe seed.py
.\venv\Scripts\python.exe app.py
```

浏览器访问 `http://127.0.0.1:5000`。`seed.py` 会写入演示资料；已有真实数据时不要将它当作无副作用的启动命令。`db.create_all()` 只创建缺失表，不会迁移已有表的字段和约束。已有数据库的结构升级需要另行处理。

从旧版本升级时，先运行 `.\venv\Scripts\python.exe migrate_join_results.py`，再启动网站。升级只新增确认字段，已有通过/驳回结果会作为未确认通知显示。测试命令为 `.\venv\Scripts\python.exe -m unittest discover -s tests -v`，测试使用独立的内存 SQLite 数据库。

管理员角色需对已有账号另行设置，当前没有初始化管理员命令。`app.py` 默认启用调试模式，仅用于本地开发。

使用献花功能前，已有数据库另需执行 `.\venv\Scripts\python.exe migrate_flowers.py`；只新增献花表，不改动现有业务表。本次开发已在本地执行成功。新库使用 `db.create_all()` 会包含献花表。
