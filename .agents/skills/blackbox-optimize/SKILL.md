# 网站优化 Skill

先读仓库根目录 [README](../../../README.md)，确认运行架构和发布状态；结合 git 状态、实际路由与测试确认哪些功能已完成。用户最新决定优先于本文件，不重复开发已有功能，不把历史草案当成待办。

## 实施方式

1. 列出涉及页面、身份、数据和验收入口。明确的小改动直接实施；影响产品结果的未决细节集中提问，有选项时用对话框。
2. 优先修改、删减和复用；保持 TypeScript/Hono 单 Worker，不因样式调整引入前端框架、ORM 或付费云服务。
3. 前端隐藏入口不能代替服务端鉴权。涉及写入、上传、审核时验证正常与失败路径。
4. 对视觉修改实际打开 PC/手机页面并截图检查，不能只看 HTML 就声称视觉通过。至少检查 1366×768、390px；拥挤布局加测低高度、360px和放大文字。键盘、触屏、减少动画不能丢功能。
5. 运行相关回归、类型和格式检查；发布前执行 `npm run deploy:check`。更新本地验收指南；架构/部署只写 README，事实结果写验证记录。代码、文档分开中文提交。仅在已获部署授权时发布，区分源码完成、本地验证、正式上线。

## 当前页面规则

- Version 1.0 补充：PC 首页第二幕也禁止内部滚动，滚轮直接切回第一幕；海报在右侧铺满可用高度并完整显示。长介绍用弹窗展开，不能因此阻断切幕。认证备选档案按入学年份从 2026 往下分组，缺年级用入队年份，未知年份最后；历史档案不隐藏。横版作品两列、竖版最多三列，横图卡保持图片比例。

- 以真实剧照、克制大字、细线和留白为主，保留作品卡、队员卡、资料预览、手机底栏。按组件整理 CSS，不不断叠加覆盖层。
- PC 首页两幕固定视口切换、背景固定；手机自然滚动。**作品列表、作品详情和资料库是长页，可以上下滑动**，照片完整可见；其他长表单、指南可内部滚动。旧“全站禁止上下滚动”已被修改。
- 第一幕“黑匣子 / 永远是你家”，下方不重复欢迎语。精选作品可为空，公告位于左下。第二幕仅保留可编辑大标题和介绍/招新正文，不显示“关于我们”“加入舞台”小标题。默认介绍：“我们是某大学生艺术团话剧队！祝大家晚安！”。大标题去标点，联系信息收成窄页尾。
- 背景回退：管理员主图→精选封面→最新审核剧照→纯色。首屏及时加载展示图，后续懒加载，不把原图当模糊背景。海报完整展示、可放大，通用图可另设手机图，不加报名按钮；二维码随海报展示，不猜测二维码内容。
- 所有选图复用已审核资料，增强界面只显示“备选图片”及缩略图；无 JS 保留原生回退。封面须属于该作品；验证取消、清除、失效图片、Esc 和手机选择。
- 全站颜色按严格 HEX 强调色派生深浅配色，危险/成功状态保留语义。每部作品可独立设置详情页主题，留空沿用全站；管理员预览不影响访客。普通文字对比度目标 4.5:1，不放开 CSP 内联样式。
- 导航为首页、作品与资料、队员与剧团、指南与鸣谢；管理只给管理员且直接点击，右上账号图标直接登录/个人中心。没有“了解黑匣子”一级入口。作品下属申请建档，资料下属补充资料，不能并列四项。桌面悬停/聚焦展开，Esc 关闭；手机点击展开。图标保留文字或可访问名称。
- 年份选项 2026—2020；旧年份不在选项内时保留，不能修改其他内容就清空。以后按用户新要求调整范围。
- 认证先找已有未绑定档案，找不到再进入新建，不并列显示两种申请。个人“代表作”不再自由填写，公开档案从演职员关系展示参与作品。

## 权限和业务不变量

- 游客浏览首页、作品、公开队员档案、已审核资料低清图/封面、公告、队员指南、鸣谢；可限频献花和提交建议。不能上传、下载原件、完整预览剧本/音视频或访问后台。
- 普通账号登录可上传（人工审核）、申请建档；认证队员可修改绑定档案和申请加入作品。待审资料仅提交人和管理员可看；管理员指南仅管理员可看。
- 认证队员低风险资料通过后直接入库；可疑格式、重复指纹等转人工，管理员可撤销。文件头检查不是恶意内容识别。视频前后端拦截，保留历史视频读取。
- 同角色允许多人/AB 角，一人允许多角色和多分工。仅作品+队员+类别+角色完全相同才重复。审核保存理由、时间、规则版本和处理人，系统审核不伪造管理员身份。
- 删除作品要求输入作品名，资料保留转其他资料。删除账号保留档案和已审核资料，不删当前或最后一位管理员；解绑降为普通账号、立即失效旧会话。没有七天回收站。
- 资料库作品在前、其他资料最后，组内提交时间降序、ID 稳定排序。分页不能无提示丢数据，搜索按作品或资料，不能同时套用客户端隐藏分页和服务端分页。
- 建议保存成功后原子记录贡献，不等邮件；贡献者不自动获队员权限。邮箱和建议正文不公开，可不公开署名。撤销资格后重新提交不能自行恢复。管理员授予时绑定账号与档案只显示一个主体。
- 管理待办按类型聚合、限制叠放数量，按管理员记录已读；处理跳到对应页面，新事件再提醒。

## 兼容与开销

- 原 Python 对照目录不动；不重置 D1、不回灌旧快照、不修改已执行迁移。新增列默认兼容，保留旧 ID、URL、密码哈希、对象键、历史和未完成上传任务。
- 删除表单字段不等于删除数据库列。保留 works、旧联系字段、下载计数等兼容数据，缺字段提交不能清空旧值。
- 动态请求检查当前账号，静态资源直接走 Static Assets。内容哈希静态文件才可长缓存，保留部署/回滚需要的旧产物。私有文件每次先授权再处理 HEAD/Range/304。
- 上传复用容量预留、完成幂等和清理队列。原图、展示图、临时任务和旧对象都计预算。先在 D1 记录删除意图再清理 R2，失败可重试，共享引用不能误删。
- 头像优先小展示图，旧头像回退原记录；批量回填需分页、可恢复、核对台账，不能静默扫描整个生产桶。客户端压缩不能替代服务端校验。
- 保持串行上传；无测量不直接加到 3–4 并发。索引依查询计划决定；子串搜索不能假装普通索引能解决。通知游标重构、旧图片批量回填、真实网络/CPU费用测量属于按需后续任务，不凭本地测试承诺线上收益。
- 不读取或提交 docs/旧密码、私密配置、真实备份和原站上传；用合成测试数据。工具拒绝时说明原因，完成不受影响部分，不换路径或脚本绕过拒绝。
