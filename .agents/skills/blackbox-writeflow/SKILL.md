# 黑匣子写入流程

这是 `blackbox-optimize` 的写入专项入口，不替代服务端权限规则。

## 身份矩阵

至少区分游客、普通账号、认证队员、管理员、禁用账号、失效会话和首次改密账号。每个写入端点列出允许身份和预期拒绝状态。

## 服务端顺序

身份/状态 → 角色 → CSRF/同源 → 输入范围 → 对象存在 → 父子归属 → 业务不变量 → 原子写入 → 可恢复清理。

前端隐藏入口、disabled 按钮和页面跳转都不算权限校验。

## 最小测试矩阵

只组合当前流程需要的状态：

- 正常成功
- 缺少或错误 CSRF
- 游客、普通账号和越权边界
- 失效会话/强制改密
- 不存在对象、父子失配、非法输入
- 重复提交、重复完成、网络结果不确定
- 相关的 400、401、403、409、413、429、500 与恢复路径

## 文件与数据库

- R2 删除前先在 D1 记录删除意图。
- 上传完成必须幂等；失败清理进入可重试路径。
- 共享对象、未完成任务和历史对象不能误删。
- 多表业务使用 batch、事务或触发器保持一致。
- 不修改已执行迁移，不重置本地或生产 D1。

## 通知专项

- 未登录或无权限返回机器可读 JSON 401/403，不返回登录 HTML。
- 客户端检查状态码、重定向、content-type 和 JSON 解析。
- 失败不能清零旧数量，应提供重新登录或重试。
- dismiss 失败不自动重复提交，先刷新核对。
- 日志只记类型和状态，不记 Cookie、CSRF、正文或私密资料。

## 输出

说明端点、允许身份、拒绝状态、幂等策略、数据一致性、测试结果和未验证路径。源码审查不得写成真实浏览器或线上已通过。
